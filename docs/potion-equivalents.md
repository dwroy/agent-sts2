# 药水换算表（2026-09-30 Roy 定）

Roy：用掉的药水不是免费的，而是以后要扣的血。「手里拿着药 = 多了一些血、攻击或格挡。」
这张表把每瓶药折算成它在**本幕 boss 战**里值多少：**血 / 伤害 / 格挡**三种等价量，放进知识库给 DeepSeek（知识前缀、`kb_potion` 工具）和 Jev（战斗题面）用。
求解器、推演和 Jev 的出牌题怎么用这张表（药水代价）见 §8（2026-09-30 Roy 定的参数，`agent/src/reflex/potion-cost.ts`）。

- 生成：`data/logdb-venv/bin/python knowledge/builders/build-potion-equivalents.py [--no-sync] [--markdown]` → `knowledge/characters/ironclad/potion-equivalents.json`（约 3 秒；`--markdown` 另外打印 §3 和 §5 的两张表）。公式自检：`python3 knowledge/builders/build-potion-equivalents.py --self-test`（不需要 DuckDB，vitest 也会跑）。
- 读取：`agent/src/knowledge/potion-equivalents.ts`（`loadPotionEquivalents`、`potionEquivalent(id, act, ascension)`；文件缺失或格式不对抛 `KnowledgeLoadError`）。
- 展示：知识前缀的「药水换算表」块（`agent/src/knowledge/render/potion-text.ts`；在经验之后、`## 数据版本` 之前）、工具 `kb_potion`、Jev 战斗题 `potion_context.potion_worth_in_act_boss`。

## 1. 口径

- **持有价值** = 这瓶药留到本幕 boss 战、在那里用掉，能省下（或回复）的血。boss 之前喝掉它，就等于付出这么多血；在 boss 战里喝不算代价。
- 三个数是同一个价值的三种说法：
  - **血** `hp`；
  - **伤害** `damage = hp ÷ r`：多打这么多伤害，boss 战缩短的回合里少挨的打正好是这么多血；
  - **格挡** `block = hp`：按 1:1（一回合用的格挡最多挡掉那回合打进来的量，所以单回合的格挡药已经在公式里封顶，见 §4.2）。
- `hold_hp = max(0, hp)`：药可以不喝，所以持有价值不会是负的（污浊药水伤到自己，`hp` 为负，持有价值 0）。
- 按**进阶**（A8、A9）和**幕**（1/2/3）分别算；某一幕某进阶的 boss 战不足 5 场（`MIN_N`）时，输入借最近的进阶（2026-09-30：A9 三幕只有 1 场，借 A8 的 22 场），JSON 里记 `inputs_asc`，文字里写「输入借 A8」。表里没有的进阶（A0–A7、A10+）查询时用最近的进阶，并在文字里说明。
- **来源**：`公式` = 日志里 boss 战实测的输入代进公式；`估` = 公式里用了估计常数（§4.8）。**数据列不采用**，原因见 §6。
- **n** = 输入用到的 boss 战场数（借用时是被借那一进阶的场数）。

## 3. 换算率（2026-09-30 生成时，342 场 boss 战）

符号：D = 我方每回合伤害，L = boss 每回合打进来的血（格挡之后），T = boss 战回合数（中位），h = 每回合攻击段数，b = 每回合打出的格挡牌数，C = 每回合出牌数，E = 每回合能量，B = 回合末格挡（均值）。
`r = L ÷ D`（每点伤害值多少血）。「每张牌 / 每点能量」是边际价值：一张平均的牌（或一点能量）多带来的 D/C（D/E）伤害 × r，加上它的格挡 B/C（B/E）按每回合 min(格挡, 打进来的) 封顶。

## 4. 公式

下面 `mean_t` 是对该幕该进阶所有 boss 战非最后一回合求平均，`mean_hit` 只对挨了打（L_t > 0）的回合求平均；`X` 是一瓶药给的数（来自 `potion-values.ts`）。

### 4.1 伤害类

| 药水 | 公式 |
|---|---|
| 火焰药水、药水形状的石头、爆炸安瓿 | `hp = Damage × r`（爆炸安瓿按 boss 单体算，多体 boss 会低估） |
| 污浊药水 | `hp = 12 × r − 12`（也打自己，按格挡不挡算）→ 负数，持有价值 0 |
| 消亡粉末（每回合 9） | 每回合多 X 伤害：战斗缩短 `T·X/(D+X)` 回合，`hp = 缩短回合 × L`，`damage = 缩短回合 × D` |
| 士兵炖汤 | 同上，X = 每回合打出的打击牌次数 × 每次打击伤害（重放一次） |
| 超巨化药水 | 下一张攻击三倍：`damage = 2 × D ÷ 每回合攻击牌数` |

### 4.2 格挡类（1:1，封顶于那回合打进来的量）

| 药水 | 公式 |
|---|---|
| 格挡药水 | `hp = mean_hit min(12, L_t)` |
| 瓶中船 | `mean_hit min(10, L_t) + mean_t min(10, L_t)`（第二次在下回合，不一定挨打） |
| 固化药水（格挡三倍） | `mean_hit min(2 × 回合末格挡_t, L_t)` |
| 铁心药水（覆甲 7） | `Σ_{k=0}^{min(7,T)−1} mean_t min(7−k, L_t)` |
| 幸运补剂（缓冲 1） | 挡掉下一次掉血：`mean_hit L_t` |

### 4.3 力量 / 敏捷

| 药水 | 公式 |
|---|---|
| 力量药水（整场 +S） | 每回合多 `X = S × h` 伤害 → 缩短 `T·X/(D+X)` 回合 × L（和 `strategy/potion-value.ts` 同一个式子） |
| 马萨雷斯的赠礼（仪式 1） | 整场平均力量 `(T−1)/2`，按上式 |
| 肌肉药水（本回合 +5） | `damage = 5 × h`，`hp = damage × r` |
| 敏捷药水（整场 +2） | `hp = T × mean_t min(2 × b_t, L_t)` |
| 速度药水（本回合 +5） | `hp = mean_hit min(5 × b_t, L_t)` |
| 异鱼之油 | 力量 1 + 敏捷 1 两式相加 |

### 4.4 回合数效果（减益）

| 药水 | 公式 |
|---|---|
| 易伤药水（3 回合） | `damage = 50% × D × min(3, T)` |
| 虚弱药水（3 回合） | `hp = min(3, T) × mean_t min(25% × 意图_t, L_t)` |
| 甲虫汁（4 回合，敌方攻击 −30%） | `hp = min(4, T) × mean_t min(30% × 意图_t, L_t)` |
| 缚魂药水（虚弱 1 + 易伤 1） | 上两式各 1 回合相加 |
| 镣铐药水（本回合敌方 −7 力量）**估** | 按敌方每回合 1 段（`ENEMY_HITS`）：`mean_hit min(7, L_t)` |

### 4.5 回血

| 药水 | 公式 |
|---|---|
| 鲜血药水（20%） | `20% × boss 战进场最大生命（中位）`（不看缺多少血） |
| 再生药水（5） | `5+4+3+2+1`（战斗不足 5 回合时截断） |
| 果汁（最大生命 +5） | `5`，**什么时候喝都一样**（`timing_free`：喝掉不算代价） |
| 瓶中精灵 **估** | `30% × 最大生命`，只在要死时起作用，自动触发、不能主动喝 |
| 龙涎香 **估** | 回血比例未知，只算「额外一回合」= `C × 每张牌价值`（日志里没出现过） |

### 4.6 能量、抽牌、随机（都是 **估**）

一张平均的牌值 `v_card`、一点能量值 `v_energy`（§3 最后一列）；抽到的牌只有 `DRAW_PLAY_SHARE = 50%` 能打出去（能量不够）。

| 药水 | 公式 |
|---|---|
| 能量药水（2） | `2 × v_energy` |
| 明耀酊剂 | `(1 + min(3, T−1)) × v_energy` |
| 痊愈药水 | `1 × v_energy + 2 × 50% × v_card` |
| 迅捷药水（3） / 明晰提取物（1 + 之后 3 回合各 1） | `抽牌数 × 50% × v_card` |
| 异蛇之油 | 手牌上限 10、手里 5 张：`5 × 50% × v_card`（耗能随机不计） |
| 发光水 | 消耗手牌再抽 10：净多 5 张 × 50% × v_card |
| 瓶装潜能、赌徒特酿、灰水 | 换牌（净 0 张），挑牌的好处按 1 张抽牌 `50% × v_card` |
| 稳定血清（2 回合） | `2 × 50% × v_card` |
| 精炼混沌（3 张免费） | `3 × v_card` |
| 预知之滴 | `v_card` |
| 液态记忆（免费） | `v_card + v_energy` |
| 复制药水 | 一张 2 费牌再打一次：`2 × v_energy` |
| 癫狂之触 | 一张 2 费牌整场免费：打出约 `1 + (T−1) × 5 ÷ 牌组` 次 × 2 × v_energy |
| 熔炉的祝福 | 手牌 5 张升级，每次打出多 25%：`5 × 25% × v_card × 打出次数` |
| 攻击 / 技能 / 无色药水 | 一张免费牌：`v_card + v_energy` |
| 能力药水 | 同上，再加能力牌的持续部分（按整场 +1 力量，§4.3） |
| 欧洛巴斯之酸 | 三张免费牌 + 能力牌持续部分 |
| 混沌药水 | `空栏位均值 × 药水池（铁甲能拿到、Common/Uncommon/Rare、有数值）的平均持有价值` |

### 4.7 其他

- 流动铜液（荆棘 3）**估**：敌方每回合 1 段 × 攻击回合占比 → 每回合多的伤害，按 §4.1 的缩短回合算。

| 常数 | 值 | 用在 |
|---|---|---|
| `DRAW_PLAY_SHARE` | 0.5 | 抽到的牌打出去的比例 |
| `HAND_SIZE` / `HAND_LIMIT` | 5 / 10 | 抽牌药的手牌数 |
| `ENEMY_HITS` | 1 | 镣铐药水、流动铜液的敌方每回合段数（`turns` 只有总伤害） |
| `POWER_LASTING_STRENGTH` | 1 | 随机能力牌的持续部分 |

| `WEAK_FACTOR` / `VULN_FACTOR` | 0.25 / 0.5 | 虚弱少 25%、易伤多 50%（游戏规则） |

## 6. 数据校验列

**做法**：A8/A9 boss 战里每次喝药（`decisions.action = 'use_potion'`）找到它那道选线题（本条自己，或者同局同层同回合、在它之前最近的一道 `combat/plan-choice*` 题：`plan-continue` 和 `plan-potion` 继续执行的是之前选的线），读题目里每个选项的推演数字：
`Δ = 「不喝」的最优线（potions_used = none，死亡样本最少、再比期望掉血）的期望整场掉血 − 选中的「喝这瓶」那条线的期望整场掉血`。
正数 = 现在喝能省血。一道题、一瓶药只算一次；选中的线同时喝两瓶的不算。418 次 boss 战喝药里 129 次有推演数字（早期版本没有推演）。按药水、按幕给中位数和 n（JSON `check`），另给全部幕和进阶合在一起的 `check_all`。

**结果**：按药水 × 幕 × 进阶分格，n 都很小：最多的是 A9 一幕的力量药水和迅捷药水（各 n=5，Δ 中位都是 0，公式分别是 9.2 和 5.0），其余每格 n ≤ 4。合在一起看（`check_all`）：

| 药水 | Δ 中位（n） | 公式持有价值（A8/A9 各幕） |
|---|---|---|
| 迅捷药水 | 0（10） | 4.6–7.8 |
| 格挡药水 | 1.4（9） | 7.4–10.1 |
| 力量药水 | 0.1（8） | 6.0–9.2 |
| 虚弱药水 | 1.2（8） | 6.2–13.0 |
| 肌肉药水 | 1.6（8） | 2.3–3.5 |
| 鲜血药水 | 0（7） | 16–17 |
| 火焰药水 | 0（7） | 4.0–5.9 |
| 能力药水 | 0.2（7） | 10.5–13.6 |
| 赌徒特酿 | 1.2（6） | 1.5–2.6 |
| 敏捷药水、易伤药水、技能药水 | 0（5） | 7.5–9.4、7.9–17.1、5.9–10.2 |
| 复制药水 | 7.8（4） | 5.5–9.9 |

**为什么不采用**：推演里「不喝」那条线写着 *later turns may use the potions still held*——它在后面几个回合照样可以喝同一瓶药（`rollout.ts`：持有的药在后面回合像 0 费牌一样可用）。所以 Δ 量的是「这回合喝还是这场晚点喝」，不是「留到 boss」的价值，大多数药自然在 0 附近（和 `notes/potion-drinks-2026-09-29.md` 的发现一致：31 次完全平手）。这一列只能说明**时机**：复制药水（7.8）、肌肉药水（1.6）这类单回合药，挑对回合确实值钱；鲜血、力量、火焰这类在同一场里早喝晚喝差不多。要拿数据直接定持有价值，需要一种不许「不喝」线后来再喝的推演（见 §9 遗留问题）。

**第二校验列（随机药水）**：`potions.random[]` 里记下的蒙特卡洛本回合增益（省血 + 多伤害 × r），A8/A9 所有战斗题的均值（JSON `mc`）。例如 A8 一幕：攻击药水 6.0（n=13，公式 5.9）、技能药水 3.7（39，公式 5.9）、无色 2.9（25，公式 5.9）、迅捷 2.5（33，公式 4.6）、能力 0.2（134，公式 10.5，本回合打不出伤害的能力牌只在持续部分）、发光水 −0.4（10，公式 7.7）。它对「拿着这瓶药的每一问」求平均，大多数问根本不该喝，所以系统性偏低；只作参考，不采用。发光水差得最多：它先消耗整手牌，本回合往往不划算，公式里的「净多 5 张牌」可能高估。

## 7. 局限

- **观察数据的混杂**：输入来自我们自己的 boss 战，牌组、遗物、打法都混在里面；A9 二幕只有 12 场，三幕借 A8。
- **boss 时钟偏乐观**：「多 X 伤害 → 缩短 X/D 回合 → 少挨 L」假设战斗时长和伤害成正比、每回合挨打一样多；boss 有阶段、召唤、复活时不成立（D 按敌人总血量下降算，召唤出来的血记 0、被格挡吃掉的伤害不算）。
- **L 是平均**：`r = L/D` 用的是所有回合的平均打进来的血（含 0）；在大招回合用的药（格挡、缓冲、虚弱）按 `mean_hit` 或逐回合 min 算，但「挑最好的回合喝」的好处没有算进去，这类药偏低估。
- **单体 boss 口径**：爆炸安瓿、缚魂药水这类群体效果按单体算，打多体 boss（同族、钳子）时低估。
- **估计常数**：抽牌、能量、随机药全部是估（§4.8），误差可能有一倍。
- **不看当前状态**：这是「本幕 boss、本进阶」的平均价值，不看这一局的牌组（`strategy/potion-value.ts` 是看当前牌组的版本，给商店题用）。缺血多少、还剩几层、药栏满没满都不在表里。
- **只到 boss 为止**：一幕的药留到二幕的价值、boss 打完还剩药的情况没有算。
- **「一张免费牌」核对过**（2026-10-03，日志里每次喝牌药）：攻击 / 技能 / 能力 / 无色药水、欧洛巴斯之酸、液态记忆加进手里的牌本回合都是 0 费
  （549 次喝这些药、86 次打出会加免费牌的牌——地狱之刃、发现、分心——加进来的牌 `energy_cost` 都是 0、打出不花能量）；遗物的改动照样加在上面：带刺手甲（能力牌 +1 费）时能力牌是 1 费
  （A4PWRULKG2JT F46 T1：0 能量喝能力药水，恶魔形态 1 费打不出，回合末弃掉）。表按「免费」算，跟规则一致；带刺手甲是单局遗物，不进表。
  对局里的模型（card-model `potionCardCost`：随机药水的蒙特卡洛牌池、能力药水建模的牌、液态记忆挑的牌）按这一局的遗物算：带刺手甲时
  能力牌 1 费，0 能量时喝能力药水什么也打不出，题面写明「a Power costs 1: Spiked Gauntlets」。

## 8. 药水代价（2026-09-30 Roy 定，已接入）

用掉的药水是以后要扣的血。代码：`agent/src/reflex/potion-cost.ts`；开关 `POTION_COST=off`（全部代价归 0，题面和排序回到接入前）。

**Roy 定的参数**：
1. 只用公式值（表的现状），不乘「能用上的概率」，不加别的系数。
2. 表每天重建一次，升进阶时也重建（`knowledge/builders/refresh-potion-equivalents.sh`，见 §9）。
3. **代价 = 这瓶药在当前进阶、当前幕的持有价值（`hold_hp`，血）**：`potionCost(id, ascension, act, fightKind)`。
   - **不做特例**：药栏满时不把价值最低的那瓶按 0 算（价值低的药代价本来就低）；什么时候喝都一样的药（果汁）也按表值（代码本来就开场直接喝它，不进选线）。
   - **boss 战代价为 0**（这就是要留它的地方）。**精英战不打折**，和走廊一样。
   - 表里没有数值的药（其他角色的、没有数值的）代价 0，题面写「no conversion value」；持有价值为 0 的（污浊药水）代价 0。表加载不了时代价 0，题面写明。
   - 进阶和幕的取法和 §1 一样：表里没有的进阶用最近的，幕按 1–3 截断。
4. **不喝会死的照喝：死亡数永远排第一。**
5. 每道战斗题都有一条「本场不用药」的线（boss 战除外，见下）。

**接到哪里**（同一个数，所有地方一致）：
- **求解器**（turn-solver）：药水牌带 `potionCost`；喝它的线分数减 `weights.hp × 代价`，`outcome.potionCost` 记下；`effectiveLoss = hpLoss + potionCost`。本回合会死的线仍是 −100000，所以救命的药照喝。
- **推演**（rollout）：后续回合的自动出牌就是这个求解器，所以它也按同样的代价决定喝不喝（这回合收益大于代价才喝）；每个样本本回合和后续回合喝掉的药按代价累计（`potionCost` 取样本均值，`laterDrinks` 记每种药在几个样本里被喝），从线的 value 里扣掉：`value = −掉血 − 药水代价 − 40 × (1 − 胜率)`。**死掉的样本不计药水代价**（药水是以后要扣的血，死了就没有以后）。
- **排序**（rollout-live `pickRolloutBest`）：有代价在场时（有线付了药水代价），**先比推演死亡样本数（少的优先），再比 value（即有效掉血 = 本场掉血 + 药水代价）**，其余次序照旧；「并列」按「有效掉血（一位小数）+ 死亡比例」相同判定。没有代价在场（boss 战、没药）时和接入前完全一样（只看 value）。**饱和局面**（每条线都把血掉光、没有样本赢）照旧按死亡、本回合掉血、敌人剩血、存活回合排，不算代价：药留在那里也没有以后（8V0H F25 T1：全部 8/8 死，算代价会选不喝熔炉的祝福）。
- **本场不用药的线**：有药可喝的非 boss 战斗题，取代码排名最靠前的不用药选项，复制一份，推演时后续回合一瓶药都不给（`noPotionLine`），作为和其他选项并列的正式选项（「— no potion this fight」，事实里有本场掉血、死亡、回合数）。如果原选项自己的推演后续回合在所有样本里都没喝药，两条就是同一条线：合并，只在原选项上标 `no_potion_fight`。不用药的线本回合全死时没有这条线，`potion_context.no_potion_line` 写明。
- **HP 护栏**、它的每场预算、setup 线和 boss 竞速的比较、随机药水蒙特卡洛的「胜过最佳不用药线」，都比「掉血 + 药水代价」。代码自己的回退线仍是「有不用药的线就不喝」（排序本身已含代价）。
- **题面**：每个选项 `potion_cost`：「fight HP loss X; potions used N (this turn: 药名 代价; later turns: 药名 in k/8 samples); potion cost Y HP (potion table, this act's held value); total Z」（没有推演时写「this turn HP loss … (no rollout …)」）；随机药水按中位样本那条线写，没模拟的药写「drinking it costs …」。`potion_context.potion_cost` 用一句话说代价的来源（持有价值 = worth 行里的「血」，boss 战为 0），没有数值的药列在 `potion_cost_zero`。原有的 `potion_worth_in_act_boss` 和留药经验块（`potion_experience`）不变。

**boss 战**：代价 0，排序、选项、分数和接入前一模一样（agent/tests/potion-cost.test.ts 用 RTF3 F17 T1 的局面锁住）；题面上每个选项的 `potion_cost` 写 0（boss fight）。**不加「本场不用药」的线**：boss 战里药没有要留到的地方，而加一条选项会改变 boss 题（需要 Roy 确认，见 experiments/potion-cost/summary.md）。

**遗留和要 Roy 定的**：
- boss 战没有「本场不用药」的线（代价 0，加选项会改 boss 题）。要不要加？
- 「本场不用药」的线取的是代码排名最靠前的不用药选项，不是推演最好的不用药打法（VSRG F27 T4：它 1/8 死，另一条不用药的线 0/8 死，后者被选为最优，排序本身没错）。要按推演挑，就得把每条不用药的线都再推演一遍，推演时间约翻倍。
- 推演后续回合的自动出牌用的是求解器的单回合分数：减益、伤害的权重比掉血高，所以代价 7.9 血的易伤药水在后续回合仍会在 8/8 个样本里被喝掉，而推演里只省了 2.5 血（VNWR F6 T1）。这正是「本场不用药」那条线要纠正的；要从根上改，得让后续回合按推演的掉血而不是单回合分数决定喝药。
- 代价按「能用上的概率」打折（§8 旧建议里的 0.7）没有做，Roy 定只用公式值。

**以前为什么去掉过代价**：batch K 之前走廊药水的持久部分按 25% 计（`POTION_LASTING`，拍脑袋的数字），d79f14f/94f81aa 去掉了。这次的代价来自日志统计的换算表，单独从分数里扣，药效本身照全额算；「喝药的线永远不会支配（dominates）不喝的同一条线」这条轴保留。

## 9. 使用和刷新

- `potionEquivalent(id, act, ascension)` 返回 `{hp, damage, block, holdHp, source, n, inputsAscension, tableAscension, formula, timingFree, check, mc}`；未知药水或没有数值的返回 null；表加载不了抛 `KnowledgeLoadError`。
- 知识前缀：「药水换算表」块（本局进阶，每瓶铁甲能拿到的药一行：一/二/三幕的血/伤害/格挡、来源和 n；块里写了生成日期和 boss 战场数）。块的顺序按「越不常变越靠前」：旧知识 → 经验 → **药水换算表** → 数据版本 → 怪物 → 遭遇 → 统计表。这张表只在手动重建时变，放在每局数据刷新不动的那一段里，同一天内前缀的稳定部分（到「## 数据版本」为止）不被它打断；**如果以后把它加进每局结束后的自动刷新，要把这块挪到「## 数据版本」之后。** 大脑缓存的前缀在表变化时重渲染。
- `kb_potion`：不给 id 返回整张表；给 id（或中文名）返回效果、日志次数、各幕数值、公式、两个校验列。
- Jev 战斗题：`potion_context.potion_worth_in_act_boss`，手里每瓶有数值的药一行，如「火焰药水：约等于 4 血 / 20 伤害 / 4 格挡（本幕 boss，A8 公式 n=88）」；表加载不了时写 `potion_worth_error`。这几行是事实；药水代价（§8）用的就是其中的「血」（持有价值）。
- **刷新**：`knowledge/builders/refresh-potion-equivalents.sh` 只在「表的生成日期不是今天（本地日期）」或「表里没有 .env 的 TARGET_ASCENSION」时重建（用日志库的 Python，先同步日志库；`--dry-run` 只说会不会重建和原因，`--force` 强制）；否则什么都不做。构建脚本 `--ascensions N` 给额外的进阶出数（场数不够时借最近进阶的输入）。上线时运维在每局赛后的知识刷新里调用它（docs/v4-go-live.md「药水代价」）。一天最多重建一次：知识前缀里这块（在「## 数据版本」之前）一天变一次，大脑前缀缓存一天冷一次；如果以后改成每局都重建，要把这块挪到「## 数据版本」之后。
- **遗留**：数据校验列需要「不喝的线后面也不许喝这瓶」的推演才能直接定持有价值（「本场不用药」的线已经是这种推演，可以用来重做校验列）；`ENEMY_HITS` 可以从怪物数据库的招式段数取代常数；表默认只有 A8/A9（TARGET_ASCENSION 另加）。
