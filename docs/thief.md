## 2. 推演以前怎么处理逃跑

出招模型里 ESCAPE_MOVE 伤害 0、后继是它自己（Escape → Escape 9 次）；FLEE_MOVE 没有后继（`nextMove` 原样返回）。所以**推演认为
草蜢和胖地精逃跑后还留在场上，什么也不做，直到策略把它打死**：「战斗结束」只算击杀，被带走的牌和钱在推演里不存在。

开关开时（`RolloutInput.escapes`）：monster-db 里意图是 Escape 的招（就这两个）结算时，敌人离场——不算击杀、不给奖励、
不触发死亡生成；场上没人了战斗结束（算「战斗结束」，不是死亡）。本回合的线把草蜢最后一层振翅打掉的，逃跑取消、下回合再逃。
佣兵带的钱在它死时传给它生成的胖地精。每个样本记下每个「小偷」的赃物：拿回（所有持有者都被杀）、被带走（有持有者逃走）、
还在场。杀戮顺序的「第一目标死了」不再把逃走的胖地精算成死了。

## 3. 题面里多了什么（只在有小偷带着东西时）

- `thief_context`（顶层，紧跟 potion_context）：每个小偷一条——`carries`（牌名按游戏的中文名，带 +；或金币数，佣兵是「目前偷了多少、
  死后给胖地精」），`turns_left`（包括本回合在内还剩几回合；「1: this turn is the last」；佣兵：不逃，胖地精出现后两回合），
  `hp`、`block`，草蜢有振翅时 `flutter`（打到 0 眩晕、本回合招取消，逃跑回合则多留一回合）；再加一句推演怎么处理逃跑。
  战斗第一帧没看到（重启又没有日志）时写「一张牌，不知道是哪张」。
- 每个选项一条 `thief`：本回合的确切结果——「kills 偷窃草蜢: 拆解 comes back」/「偷窃草蜢 left at 23 HP, leaves at the end of
  next turn」/ 末回合「leaves at the end of this turn with 拆解」/ 打掉最后一层振翅「stunned, …(its Escape: one more turn)」，
  再加推演的「killed before it leaves in k/n samples, left with it in m/n」；有杀戮顺序时，另一个顺序拿回得更多也写上。
  只有数字和事实，没有建议、没有代码分数（tests/thief-facts.test.ts 的审计）。
- 选项覆盖：小偷的最后一回合，如果有一条幸存线能杀它而选项里没有，就加进来（不喝药的优先）；不是最后一回合，就把推演里
  「逃走前拿回」样本最多的那条线放进选项（各杀戮顺序取最多；并列看推演价值），已经在选项里的就保留，不被药水选项挤掉。只用求解器
  本来就生成的线。
- 决策日志多一个 `thief`：小偷、本回合能杀它的选项 key、加入/保留的覆盖线、所选的线有没有杀它。
- 失败保护（直接上线跑，Dai 10-02）：小偷的任何一步出错，这次决策就丢掉全部小偷事实，按开关关的样子出题（推演不带逃跑重跑一次）；
  记战斗第一帧的那一步永远不抛错；`THIEF_FACTS` 写错只给警告（按开），不会让程序起不来。tests/thief.test.ts 里有一条：第一帧记录坏了时，
  题面和开关关逐字节相同。
- DeepSeek 不接战斗题（Dai 09-28 起战斗不升级；FIGHT_PLAN 线上是 off；最后一次 DeepSeek 选线是 09-25）；事实同样写在决策自己的
  `state`/`questions` 里，以后升级回来也带着。按牌出的后备题（combat.ts，求解器没有线时）没有加。

没有改：排序里不加任何代价；求解器本回合的数字不变（**振翅打到 0 取消本回合攻击，求解器还没模型**：那条线的 hp_lost 仍算着
那一下，`thief` 事实里写明了，见 §6）。

## 4. 奖励屏（不在开关后面）

跳过卡牌奖励后，旧代码把所有 SpecialCard 一起过滤掉，如果先跳了卡牌奖励，「取回你被偷走的牌」就领不到（日志里没发生过：它总排在
Card 前面）。日志里只有两种 SpecialCard：取回被偷的牌（141 次）和灯火钥匙（5 次），146 次领取之后都直接是下一个领取，从没打开过
选牌。现在这两种在跳过之后照样领，而且排在会打开选牌的奖励（Card、LinkedRewardSet、其他 SpecialCard）前面；别的 SpecialCard
保留原来的保护。
