# 每局构筑记录（#35）

Roy 2026-10-22 要求每道构筑题附本局已做的选择及短理由。实现复用 run journal 与原答案 `reason`，不增加模型请求，也不保存额外推理全文。

`memory.construction_log` 随拿牌、商店、休息、删牌/升级/变牌选择、事件、礼包、幕末选择、幕初路线及运行计划题给出，位于 journal 稳定历史之后。战斗和战斗内选牌不附此段。首句固定为“本局已做的选择，不是规则；运行计划的转向条件照旧有效。” #33 的知识工具模式保留该局内状态，不把它改成查询工具。

每行有层、动作、牌/跳过时提供的选项、理由和来源。动作从已执行决策和后续实际 `run.deck` 的 ID/升级状态多重集差分确认，重复牌分别计数；未见牌组变化的拿牌或选择不提前记成完成。成功跳过立即记选项，失败、未派发和 shadow 不记成实际选择。跨层才确认的直接拿牌/买牌记原动作层数。事件的加牌与变牌记实际结果；没有对应动作证据时写“状态观察（来源未知）”，不猜机制或模型理由。

模型理由按 Unicode 字符截到 20 字，代码和 Jev 动作的理由写来源。知识工具模式只调整原 `reason` 的 schema 说明，不改屏幕生成的问题正文，也不为超长理由重问。单次计划后续步骤通过原 plan reference 沿用该次短理由；理由缺失明确标出。

上限为开头 4 条加最近 36 条。开头条目作为本局方向起点固定保留，不用策略关键词判断价值；中间超过上限的条目移出题面并累计 `omitted`。卡名最多 48 字，超长牌串截断标 `…`；完整选项仍在原状态日志。题面牌串最多 140 字，整个新增字符串最多 20,000 个 JavaScript 字符。历史原行不删除。

状态和已执行决策继续落入原 `states.jsonl` / `decisions.jsonl`，进程重启按原 journal replay 重建。运行中 SL 使用原战斗入口 journal 快照恢复；成功 SL 决策行另存 `construction_restore`，重启重放即使跳过该条未派发动作，也先恢复构筑快照。跨层回滚恢复原层检查点并去掉放弃的未来。回到相同牌组的正常拿/删序列不会被误当回滚。

`logs/construction-log.jsonl` 在记录变化（含 SL 恢复改变记录）后追加局号与精简快照，旧尝试保留，读取指定局最后一条。重启重放不重复输出整段历史，只补当前快照；写盘失败沿原日志原则保留局内运行。`learner/evidence_summary.py` 提供最新快照原行 offset/bytes/SHA，复盘模板列入直接材料来源；历史局没有此日志时继续查原 states/decisions，不补造理由。

该状态输入按 #35 对所有角色一致提供，包含铁甲战士，可能影响模型后续构筑选择；这是 Roy 指定的局内历史输入变更。牌值、知识内容、执行闸和模型请求次数没有增加或调整。开发交付不代表发布；版本编号、自然边界上线和首局读回由集成员与 ops 沿原流程完成。撤回本功能提交可回退题面和记录链路，已写历史日志保留。
