## 1. 原则

1. **分层决策，每层有时间预算。**

   | 层 | 谁 | 场景 |
   |---|---|---|
   | L0 直接执行 | 代码 | 只有一个合法动作、确认、拾取、显然的结束回合 |
   | L1 快速层 | 代码候选 + Jev + 经验策略 | 所有战斗回合；常规拿牌、商店、休息、事件、选路 |
   | L2 大脑 | Codex | 每幕开头的整幕计划；Boss 前最后准备；罕见或关键事件；计划失效后的重规划 |

2. **所有计算限时、随时可停。** B2/B3 在预算内尽量多跑，C2 照常淘汰；时间到就用当前估计、误差和样本数决策，并如实标注。这替换 V5-R341 的“必需完整计算”语义；C1 故障出口保留。
3. **大脑先计划、后执行，遇到例外才介入。** 大脑给出一段计划，L1 按计划执行；计划没覆盖的情况才再调用大脑。
4. **经验驱动的快速策略。** 学习者把经验沉淀为 L1 可直接使用的规则和打分，L1 查用而不是每次问模型。游戏知识仍只由学习者从对局证据得出。
5. **推理强度不降。** 大脑保持 xhigh；限时靠更少的调用和硬截止，超时用 L1 的答案兜底。

## 3. 分阶段

| 阶段 | 内容 | 改变对局行为 | 依赖 |
|---|---|---|---|
| H1 | 时间预算层与限时计算 | 是 | 无，最先做 |
| H2 | 大脑“计划—执行” | 先 shadow，后 on | H1 |
| H3 | 经验快速策略（学习者） | 知识更新 | H2 |
| H4 | 预算调参与持续评估 | 由 Roy 定 | H1 起持续 |

### H1 时间预算层与限时计算

- 统一的预算框架：每个决策入口带预算；超时返回当前最佳，并记录 `budget_ms`、实际耗时、是否超时、使用的兜底。
- B2/B3 改为限时：按预算分批采样，C2 淘汰保留；到时用当前估计，完成状态记为 `complete_budget` 或 `partial`，样本数和误差进日志与题面。
- 低可信 Boss：B2 少量采样或跳过（见第 2 节）。
- 预计算：进 Boss 房时、敌方回合和动画期间，预先计算下一回合候选；不改变合法性检查与执行闸。
- SL 重试复用首试已有的计算结果。
- 已有 shadow 功能（G2 全局评估、F48 联合汇总等）必须服从预算：超预算就跳过并记 unknown，不再延长等待。
- 验收：固定测试；2 局完整自然局的每局用时、各类决策延迟 p50/p90/最大值；G1c 漏斗不明显变差。

### H2 大脑“计划—执行”

- 整幕计划题（L2）输出结构化计划：路线偏好与风险、拿牌优先与避免、休息与升级原则、构筑方向（沿用 `run_plan.construction` 和 want/avoid），以及大脑自己写的“遇到什么就叫醒我”的条件（例如 `pivot_if`、`checkpoint`）。
- L1 执行器按计划处理常规的拿牌、选路、休息、事件和商店。遇到计划没覆盖的情况，或者满足大脑写的触发条件，才调用 L2。例如拿到改变方向的遗物、关键牌出现、血量跌破计划里的阈值、意外事件、Boss 前准备。
- 触发条件来自大脑的计划和学习者的经验，代码里不写游戏知识。
- 先 shadow：L1 执行器给出它会怎么选，但仍由大脑实际决定；2 局对比两者的一致率和分歧题。通过后切 on。
- 目标：L2 调用降到每局 12–15 次。

### H3 经验快速策略（学习者）

- 学习者把已有经验整理成 L1 能直接使用的规则和打分，例如拿牌估值、休息与升级的取舍、用药时机、路线风险。每条带证据局，按[学习要求闭环](learning-requests.md)交付并接入消费者读回。
- Jev 题面保持短小。原 V5-S 的 P4（Jev 只在并列组里仲裁）可以在这一阶段重新评估；它涉及药水规则变化，仍需 Roy 另行确认。

### H4 预算调参与持续评估

- ops 每 10 局输出每局用时分布和 G1c 分段漏斗，两者放在一起看。
- 预算初值的调整由 Roy 决定；实现者只给数据和建议。

## 5. 约束

- **学习协议**：开发会话不写入任何牌、怪物、机制或数值事实。时间预算是工程参数，不是游戏知识。
- **角色隔离**：只改 Silent；其他角色默认关闭，铁甲战士逐题等价。
- **模型**：大脑保持 gpt-6.1-sol / xhigh，普通服务档。
- **SL 与药水**：原规则不变，只改重试的计算复用和预算。
- **流程**：一个功能一个工作树；固定测试；不运行 play；提交前 gitleaks；每个行为阶段由 ops 单独发布、编号、发规则变更双通知、做精确树宿主检查。

## 7. 风险

- 计算减少后决策更粗，短期胜率可能下降。已有数据显示 V5 的提升出现在“必需完整计算”上线之前，它的收益没有被证明，但这一点仍要用 H1 之后的数据验证。
- 低样本带来更大的噪声，必须把样本数和误差如实带给 Jev 和大脑。
- L1 执行器的质量取决于学习者沉淀的经验，H2 shadow 阶段要看分歧题。
