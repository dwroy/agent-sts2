# boss 战整场模拟器（里程碑 B1、B1.5）

2026-09-30 Dai 定：A8 的对局大多死在 boss（F17/F33/F48）。决定 boss 战输赢的有两件事：boss 战十几个回合怎么打，牌组够不够打过 boss。这两件事现在分别靠 5 回合推演和 boss 时钟判断，可推演往后几回合系统性多报掉血，boss 时钟在输局里的实打只有估值的 0.72。下一步要做「boss 战整场规划」（B2）和「构筑按模拟打 boss 的结果判断」（B3），两者共用一个底座，就是这里的**整场模拟器**。B1 只做模拟器本身和它的回测，B1.5 把它修准；两者都**不接进对局，也不改 Jev 或 DeepSeek 的题面**。

**B1.5 结论**（§6；汇总在 experiments/boss-sim/b15-val.md 和 b15-summary.json）：

- **按时间切分**：424 场按局的时间切开，较早的 283 场作调参集，较晚的 141 场作验证集。所有参数只在调参集上定，数字以验证集为准。B1 的伤害权重 0.5 在调参集上重选，仍是 0.5。
- **偏差诊断**：从日志里的真实局面只模拟一回合，×0.5 的策略每回合掉血 6.5，实际 6.8。所以单回合的出牌不偏进攻；模拟多掉的血主要来自打过几回合以后局面变差。修正了几处：回合遗物（烛台等）、策略在第 1 回合就把药水喝光、击杀顺序、起点回合改由策略出。更防守的策略（HP 权重、威胁项、×0.3）能把被打穿的血压到和实际一样，但胜负预测反而变差，所以没有采用。
- **验证集**：
  - 第 1 回合起：Brier 0.187 → 0.165；再经调参集上拟合的 Platt 映射，降到 0.147。AUC 0.849。校准后预测平均胜率 0.618，实际 0.593；n ≥ 20 的桶误差最大 6 个百分点。
  - 战前起点（B3 用）：校准后 Brier 0.146，桶误差最大 3.9 个百分点。
  - 第 5 回合起：校准后 0.094（B1 0.096）。
  - 赢局掉血误差中位 +5（B1 +8）。第 2–7 回合被打穿的血，第 1 回合起是实际的 1.10 倍，第 5 回合起 1.17 倍，没有全部达到 10% 的目标。按 boss 看，帝王蟹 1.6 倍、实验体 2.5 倍，差得最多。
- **B2 / B3 底座**：
  - 候选线比较：30 个战中局面里，Jev 选的线有 11 个排第 1，24 个和最优线在 2 个标准误以内；每个局面中位 1.3 秒。
  - 牌组配对：打同族时去掉唯一的群伤牌，胜率掉 35 个百分点；加一张打击小幅变差。
  - 能不能接 B2 / B3、还缺什么，见 §8。

B1 的结论（回测全文见 experiments/boss-sim/report.md；B1.5 之后的数见 §6）：

- **第 1 回合起预测胜负**：424 场 A7–A9 boss 战，其中 422 场可回测，每场 200 个样本。模拟的 Brier 为 0.182、AUC 0.87，比 5 回合推演（0.258）、boss 时钟（0.365）和常数基线（0.242）都准。在 fight-value 模型没训练过的 111 场上（留出集），模拟 0.186，推演换成模型终值是 0.213。
- **第 5 回合起**：Brier 0.092；赢局掉血误差中位 +3，回合数误差中位 0。
- **偏差方向**：整体偏悲观，预测平均胜率 0.45，实际 0.59。逐回合看，敌人来袭和我方伤害都对得上，但同样的来袭下，模拟每回合多掉约 30% 的血。B1 把原因归到模拟的策略（solver 的最优线）比实际挡得少；B1.5 的诊断见 §6.2。
- **速度**：24 个 worker 并行时，单个局面 300 样本中位 0.30 秒、最慢 0.97 秒；6 条线各 300 样本中位 2.2 秒、最慢 5.2 秒。都远低于 10 秒的目标。

## 1. 用法

```ts
import { BossSimPool, calibratedWinProb, compareLines, redealInput, runBestOrder, runBossSim } from "../sim/boss-sim.js";

// input: RolloutInput，和 5 回合推演用的同一个（rollout-live boardRolloutInput + 抽牌堆/弃牌堆 + meta）
const serial = runBossSim(input, [lineA, lineB], { samples: 300, seed: 1 });   // 单线程
const pool = new BossSimPool();                                               // 默认核数 − 4，最多 24
const res = await pool.run(input, [lineA, lineB], { samples: 300, seed: 1 }); // 数和 serial 完全一样
const diff = compareLines(res.lines[0]!, res.lines[1]!);                      // 配对差：胜率差 ± 标准误
await pool.close();

// B1.5
runBossSim(input, [null], opts);                                              // 不给线：起点回合也由策略出
const pre = redealInput(input, { fresh: true, hp: entryHp });                 // 战前起点：牌组洗牌、手牌空、进场血量
const best = await runBestOrder((i, l, o) => pool.run(i, l, o), input, lines, opts); // 每条线取最好的击杀顺序
calibratedWinProb(best.lines[0]!.winProb, 300, "mid");                        // 绝对胜率用 Platt 映射（start / mid / pre）
```

每条线的输出（`BossSimLineResult`）包括：

- 胜率，以及赢 / 死 / 到上限各多少样本；
- 掉血分布：全部样本一起算（死了算全部血量加复活的血量）；赢的样本另算一份；每份给均值、中位、p25、p75、p90、最小、最大；
- 回合数分布（全部样本 / 只算赢的样本）；
- 死亡回合，按回合计数，另给分布；
- 每种药水有多少样本喝了；
- 没赢的样本里敌人平均还剩多少血；
- 逐回合数据：还在打的样本数，平均掉血、伤害、来袭、被打穿的血，到这回合末还活着 / 已赢的样本数；
- 每个样本的结果（按样本序号排）。

回测工具在 tools/boss-sim/：

- `extract.py`：从日志库取 boss 战，按偏移读 states.jsonl 的开场局面和第 5 回合局面；
- `backtest.ts`：逐场跑模拟、5 回合推演、boss 时钟，可分片并行；
- `report.py`：出报告；
- `bench.ts`：测速度；
- `trace.ts`：单场单样本逐回合对照日志，调试用；
- `backtest-board.ts`：把日志状态按实盘规划器的方式还原成盘面。

复现命令见 §9。

## 2. 设计

**完全复用推演**。每个样本都跑 src/strategy/rollout.ts 里的 `simulate`，只是入口换成新导出的 `simulateFight(input, line, maxTurns, seed)`。推演原有的这些机制全部照用，不另写一套卡牌或怪物规则：

- 抽牌堆洗牌和抽牌，弃牌堆洗回；
- 怪物按出招模型（move-model 的后继计数）出招，伤害按 monster-db 的按进阶数值，另外处理力量、易伤、虚弱、格挡、覆甲、各种自身增益、状态牌、给我方上的减益；
- 我方的持续能力（恶魔形态、燃烧、金属化……）、遗物能量和格挡、复活；
- 药水：手里建了模的药水当作 0 费、只能用一次的牌，带 potion-cost 的代价；boss 战代价为 0，solver 觉得有用就喝；
- 召唤（死亡时生成）、幻象复活、分段重连、瀑布巨兽的空壳爆炸、实验体换阶段、沙坑。

每回合的出牌由 turn-solver 决定，节点上限 1500；实际平均每回合只用约 47 个节点，上限基本碰不到。

和推演不同的地方有四点：

1. **没有窗口**，一直打到 boss 死或我方死。上限 30 回合（日志里 boss 战最长 24 回合），到上限记为「未分胜负」（capped），不算赢。回测里一次都没碰到上限。
2. **没有终值估计，也没有时间预算**。每个样本只由（输入、线、种子）决定。
3. **整场脚本**（`fullFight`）。只在整场模拟里打开，5 回合推演里全部关闭。在同样 62 个日志局面上核对过，推演输出和改动前 aba384c 逐字节相同。长时间模拟会暴露一些出招模型的问题，这里逐个补上：
   - 出招模型的后继计数里混着「死了 / 换阶段那回合」的转移，比如巨兽每招后有约 10% 接 EXPLODE。整场模拟里，活着的敌人不会用死亡招式（`DEATH_MOVES`），也不会用别的阶段的招式（`PHASE_MOVES`，实验体三个阶段各用自己的招式，新阶段从第一招开始）。
   - 仪式兽：Plow 阈值（A8 150、A9 160）第 2 回合才出现，按 monster-db 的首见回合补上（`shriekFrom`）。阈值没打穿之前一直用 Plow，打穿时被击晕、当回合出招作废，之后进入 Beast Cry 循环。
   - 女王：火炬头活着时一直用 Burn Bright For Me，火炬头死后转 Off With Your Head。这是日志 15 场全部如此归纳出来的。
   - 乐加维林族母：Asleep 3 回合；第一次掉血就醒，当回合眩晕、下回合 Slash；醒来时覆甲和格挡清零（日志：睡着时格挡 12/12/11，第 4 回合为 0）。
   - 越打越强的招式：实验体 Multi Claw 每用一次加一段（10×3、10×4……）；巨兽 Pressure Gun 每用一次加 5（A8 20/25/30，`growth` 取自 monster-db 的 moveBaseDamages）。
   - **每个敌人用自己的随机流选招**：种子由样本序号和敌人在场上的位置决定。这样两条线在同一个样本里看到的敌人出招相同（common random numbers），和我方怎么抽牌、打哪条线无关。
   - **抽牌抽到的牌能打出去**（`knownDraws`）。推演里抽牌牌抽到的牌直接进弃牌堆，用处只在 solver 的分数里记一个固定值，所以每回合实际少打约 0.8 张牌；日志里 boss 战牌组平均 23.5 张，其中 3.5 张会抽牌。整场模拟把抽牌堆顶上的牌作为已知的 `drawn` 交给 solver，代替期望值的抽牌，对应实盘「抽完牌重新规划」。代价是策略提前知道会抽到什么，略偏乐观。
4. **策略的伤害权重乘 0.5**（`BOSS_SIM_DAMAGE_SCALE`，通过 turn-solver 新增的 `SolverInput.damageScale` 实现，实盘不设）。日志里的 boss 战比 solver 的最优线挡得多，见 §5.4。依次试了 1、0.7、0.5、0.3，0.5 的 Brier 最好。B1 是在全部场次上选的，属于样本内；B1.5 只在调参集上重选，结果仍是 0.5（§6.4）。
5. **B1.5 的几处改动**（§6.3）：
   - 起点回合可以不给线，由策略出；
   - 战前起点 `redealInput`；
   - 回合遗物 `fightRelics`；
   - 喝药要付 0.5 × 药水表的 holdHp（`potionHold`）；
   - 每条线取最好的击杀顺序 `runBestOrder`；
   - HP 权重和威胁项做成开关（`hpScale` / `threat`，默认关）；
   - 绝对胜率用 Platt 映射 `calibratedWinProb`。

**Common random numbers**：样本 i 的种子是 `sampleSeed(seed, i)`，和是哪条线、哪副牌组无关，所以比较两条线（B2）或加不加一张牌（B3）时，两边第 i 个样本用同一个种子。`compareLines` 按样本序号给出配对差和标准误。测试核对了三点：同一条线跑两遍逐样本相同；两条不同的线在双方都还在打的回合里，敌人出招序列相同；并行结果和串行完全一致。

**并行**：`BossSimPool` 把（线、样本）任务切成小块，谁空闲就发给谁。worker 是 TypeScript，经 tsx 载入；在 vitest 里也能用。worker 启动一次约 0.44 秒，一个进程里建一个池反复用即可。每个任务只由输入和种子决定，所以池的结果和 `runBossSim` 串行结果逐样本相同，有测试核对。

**对实盘的改动**：只有三处，都不改变实盘行为。

- rollout.ts 多了 `fullFight` 分支和 `simulateFight` 导出。
- turn-solver 多了可选的 `damageScale` 字段，实盘不设。
- rollout-live 的 `enemyTable` 多带两个字段 `growth` 和 `shriekFrom`，只有整场模拟会读。
- B1.5：
  - turn-solver 多了可选的 `hpScale`，实盘不设；
  - rollout.ts 的 `simulate` 允许不给起点线（只有 simulateFight 会传 null），新增 `RolloutInput.fightRelics`，只在 `fullFight` 里读；
  - `policyWeights` 在没设模拟开关时返回空，和原来的 `damageScale` 分支等价；
  - rollout-live 新增 `fightRelicsOf`，实盘不调用。
  
  tests/boss-sim.test.ts 在合成盘面上用 solver 和 5 回合推演的数字做了一份摘要。这份摘要和改动前（89b8cd0）逐字节相同，测试把它固定为常量。

src/sim/ 不被 src 里任何别的模块引用，tests/rollout.test.ts 会检查这一点。

## 3. 速度

在 32 核机器上测，测时机器负载约 12；用 tools/boss-sim/bench.ts，取 12 场分布在全部数据里的 boss 战，从第 1 回合开始：

| 项目 | 中位 | 最慢 |
|---|---|---|
| 单个样本（打完一整场，这 12 场平均约 9 回合） | 8.8 ms | 50 ms |
| 100 样本，串行 | 0.78 s | 2.2 s |
| 100 样本，24 个 worker | 0.11 s | 0.33 s |
| 300 样本，串行 | 2.1 s | 6.2 s |
| **300 样本，24 个 worker** | **0.30 s** | **0.97 s** |
| 6 条线 × 300 样本，24 个 worker | 2.2 s | 5.2 s |
| 池启动（24 个 worker） | 0.44 s | — |

每回合的耗时主要花在 solver 上，每回合约 1 ms。耗时最长的是回合多的场（族母 17 回合一场 50 ms）和帝王蟹（两个敌人，候选线多）。10 秒的目标有很大余量，现在不需要降级。如果以后要降级，可以按这个顺序：先把样本减到 100（胜率标准误约 ±5%），再把 `policyNodes` 降到 300，最后换用更简单的一回合策略。

各场通用的缺口：

- 随机药水（Swift、Attack / Skill / Power / Colorless Potion）不在模拟手里（实盘用 potion-mc 另算）。模拟每场平均喝 0.96 瓶，实际 1.25 瓶。

## 5. 回测

口径：用 tools/boss-sim/extract.py 取日志库 fights 视图里 room = boss 的战斗，A7–A9 共 424 场（2026-09-26 至 09-30）。起点有两个：

- 第 1 回合第一个决策帧。不用 observed 帧，因为 164 场的第一帧是在抽牌之前记的，手里没牌。
- 第 5 回合第一个决策帧（打到第 5 回合的 412 场）。

实际结果：

- 战斗结束血量 = min(最后一个战斗帧, 战后第一帧)，死了记 0，同 docs/eval.md §7.2；
- 掉血 = 起点血量 − 结束血量；
- 回合数 = 从起点那回合算起。

有 2 场的第 1 回合规划器没调用 solver，算不了，所以第 1 回合起是 422 场。

对比对象都在同一个状态上离线重算：

- **推演**：rolloutDecision，线上的设置（5 回合 × 8 样本、门控终值，这里不限时），取同一条线的「到战斗结束的预期掉血 / 胜率」；
- **推演-模型**：同一推演换成 fight-value 模型终值（w = 1）。这个模型是在这些战斗上训练的，所以全集上的数是样本内的，偏乐观；**留出集**只算模型训练行（.cache/fight-value-rows.jsonl，324 局）里没有的局，共 112 场 boss 战；
- **时钟**：boss-clock.ts 按实际进场血量重算，只有第 1 回合。时钟不给概率，胜负预测按「够」（gap 0）算 1、否则 0；AUC 用 −gap 算；赢局掉血 = 每回合掉血 × 时钟回合数。

误差一律是 预测 − 实际。

### 5.4 偏差：出在哪里

逐回合对照第 1 回合起、日志里这一回合还在打的场次，第 2–6 回合平均（experiments/boss-sim/report.md「逐回合」）：

- 敌人来袭：模拟 16.4，实际 16.6（第 2 回合），各回合都在 ±1 以内。出招模型没问题。
- 我方伤害：模拟 29.0，实际 29.8。没问题。
- 掉血：模拟 9.3，实际 7.2，**多约 30%**；伤害权重乘 1 时多约 45%。在同样的来袭下模拟挡得少，是**我方策略**的问题：solver 的最优线比实际对局更偏进攻。第 1 回合手牌和意图都是真的，只是线不同：solver 最优线掉 2.8，Jev 实际选的线掉 1.8。把伤害权重调低只能沿 solver 自己的取舍往回挪：乘 0.3 时掉血 8.6，伤害却只剩 26.0。实际对局在「同样伤害、更少掉血」的位置，这个参数调不到那里。

|---|---|---|---|---|
| 帝王蟹 | 27.1 / 28.0 | **17.5 / 11.0** | 36.6 / 35.5 | 0.02 / 0.23 |
| 女王 | 25.6 / 27.5 | **16.9 / 11.1** | 35.1 / 42.7 | 0.00 / 0.20 |
| 实验体 | 41.8 / 38.1 | **29.6 / 12.6** | 39.1 / 39.8 | 0.00 / 0.22 |
| 幻影墨 | 14.6 / 14.8 | 7.7 / 7.2 | 14.5 / 19.6 | 0.59 / 0.87 |
| 仪式兽 | 16.4 / 16.0 | 7.9 / 6.4 | 28.8 / 28.2 | 0.58 / 0.83 |
| 知识恶魔 | 16.7 / 16.7 | 8.2 / 7.0 | 34.7 / 41.0 | 0.28 / 0.49 |

| 灵魂鱼 | 9.6 / 10.2 | 4.8 / 6.3 | 22.4 / 21.8 | 0.81 / 0.82 |

偏差最大的三个 boss 和原因：

- **帝王蟹**：来袭和伤害都对，但模拟每回合多被打穿 6.5 血，是所有 boss 里差得最多的。solver 在这一场有专门的「两只钳子血量平衡」项，加上伤害优先，线都偏进攻；实际对局每回合挡得多（第一回合的例子：solver 最优线掉 18，Jev 选的线掉 1）。后续回合的背后攻击没建模，模拟里的来袭本该更高，所以算上它模拟会更悲观。原因属于**策略打得比实际差**。
- **女王**：模拟的伤害比实际低 18%（35 对 43），多被打穿 5.8 血。不给击杀顺序时伤害更低（29 对 43）：solver 打 minion 打折，不去打火炬头，火炬头一直活着。给了「先杀火炬头」之后，打穿的血仍然多。原因是**策略**（You Are Mine 之后一直虚弱加脆弱，挡的效率低，实际对局靠的是牌组里的大格挡牌加药水），另外火炬头招式用的是显示值，属于**怪物模型的近似**。
- **实验体**：第二阶段的 Multi Claw 每回合多一段，模拟被打穿 29.6，实际 12.6。实际对局在第二阶段几乎全力防守，solver 的一回合策略看不到「下回合多一段」，照常进攻。原因是**策略看不到后续回合**。只有 9 场。

另外：

- 幻影墨和知识恶魔是**伤害偏低**：幻影墨有 Slippery，实际对局会用多段攻击去剥层数；知识恶魔给 Sloth 后每回合最多 3 张，实际对局选大牌。
- 贪得无厌者是唯一偏乐观的 boss，模拟的伤害比实际高 23%。

### 6.2 诊断：模拟多掉的血从哪里来

**Jev 实际怎么选线**（tools/boss-sim/choices.py，调参集 2383 次 plan-choice）：72% 选 solver 的第一条线。另外 28% 选了别的线，平均每回合少掉 3.2 血，同时少打 8.3 伤害。偏离最多的是女王（58%）、帝王蟹（45%）、实验体（43%）。只看每回合的第一次决策：solver 第一条线自己预测掉 9.3 血，Jev 选的线预测掉 8.2，这一回合实际掉 6.6。

**单回合回放**（tools/boss-sim/turn-replay.ts，b15-replay.json）：取日志里 Jev 规划过的每一个 boss 回合，从当时的真实局面出发，让模拟的策略只打这一回合，和日志里这一回合的实际掉血对比。调参集 1451 个回合，每回合平均：

| 策略 | 掉血 | 伤害 |
|---|---|---|
| 实际 | 6.80 | 25.6 |
| solver 第一条线（实盘权重 ×1） | 8.36 | 30.4 |
| 伤害权重 ×0.5 | 6.52 | 26.0 |
| ×0.5，手牌从抽牌堆重新发 | 6.80 | 25.7 |

从真实局面出发，×0.5 的策略每回合并不比实际多掉血。按「来袭 / 当前血量」分段看（这一段和下面按 boss 的数用的是另一次回放，1496 个回合，实际每回合 6.60），×0.5 在来袭小的回合挡多了（< 0.2 段：3.45 对实际 4.55），在来袭大的回合挡少了（≥ 0.7 段：10.97 对 9.03）。换成「×1 + 威胁项 2」（HP 权重乘以 1 + 2 × 来袭 / 血量），各段都能对上：4.17 / 7.93 / 10.68 / 9.64，实际是 4.55 / 8.09 / 10.10 / 9.03。按 boss 看，×0.5 在帝王蟹（13.7 对 10.0）、女王（12.7 对 10.6）、永恒镜（12.1 对 8.8）挡少了；在幻影墨（3.3 对 5.6）、仪式兽（4.7 对 6.1）挡多了。验证集上每回合的差更大一些：×0.5 掉 8.73，实际 7.55。

**同一批回合，整场模拟打过来是多少**：还是 ×0.5 的策略（调参阶段「策略起手 ×0.5」的配置），但从第 1 回合一路模拟到这一回合，逐回合的掉血和单回合回放、实际放在一起比（调参集，都是 Jev 规划过的回合）：

| 回合 | 场 | 实际 | 单回合回放 | 整场模拟 |
|---|---|---|---|---|
| 2 | 208 | 8.2 | 8.0 | 9.7 |
| 3 | 203 | 7.9 | 7.8 | 10.7 |
| 4 | 158 | 6.1 | 7.2 | 8.9 |
| 5 | 160 | 7.9 | 6.8 | 10.2 |

所以多掉的血，大部分不是「这一回合的出牌偏进攻」，而是**模拟打过几个回合以后的局面比实际差**。逐个核对过的局面量：

- 能量：修之前，第 2 回合有 36/311 场比实际少 1–2 点。原因是烛台之类的回合遗物没建模，修后 3.22 对 3.25。
- 我方虚弱 / 易伤、力量、回合开始时的格挡：都接近，力量到第 7 回合落后约 0.7。
- 敌人来袭：逐个 boss 看均值、标准差和为 0 的比例，都对得上，只有实验体偏高（38.7 对 35.2）。
- 药水：修之前，策略在第 1 回合就喝掉约 80% 的药水，实际第 1 回合只喝 40%。而且实际每场比模拟多喝约 0.3 瓶，这部分是没建模的随机药水。

把策略调得更防守（×0.3、HP 权重 ×1.5、威胁项 1–2），整场模拟被打穿的血确实降下来了（第 5 回合起比值到 1.0），但战斗拖长，模拟胜率反而更低，Brier 变差（§6.4）。也就是说，「策略偏进攻」只能解释单回合里的一小部分差距；整场的偏差还来自跨回合的东西：没建模的药水和遗物，以及 Jev 靠推演做的跨回合安排（B2 的比较本身也要用到这一点）。

### 6.3 改了什么（只在整场模拟里生效）

1. **起点回合也由策略出**：`simulateFight(input, null, …)`，B1 用的是 solver 在实盘权重下的第一条线。B2 比较线时仍然传具体的线。
2. **回合遗物**：`RolloutInput.fightRelics`，由 rollout-live 的 `fightRelicsOf` 生成。包括烛台第 2 回合 +2 能量、吊灯第 3 回合 +3 能量、开心小花按计数每 3 回合 +1 能量、船夹板第 2 回合 14 格挡。数值取自日志：持有这些遗物的 boss 战分别有 22、15、42、13 场，拿它们和不持有的场次比回合开始时的能量和格挡。只有 `fullFight` 读这个字段。
3. **药水留着用**：策略每喝一瓶药，要付 0.5 × 药水表里这瓶药的 holdHp（`potionHold`，模拟专用，实盘 boss 战的药水代价仍是 0）。
4. **击杀顺序取最好**：`fightOrders` / `runBestOrder`。每条线在「solver 自选目标」和每一种击杀顺序下各跑一次，用同一组种子，保留胜率最高的一种，和推演的做法一致。涉及帝王蟹、同族、女王。B1 只给女王固定了「先杀火炬头」。
5. **伤害权重 0.5** 在调参集上重选；HP 权重倍数（`hpScale`）和威胁项（`threat`，turn-solver 新增的 `SolverInput.hpScale`）做成开关，默认关。
6. **Platt 映射**（`BOSS_SIM_PLATT` / `calibratedWinProb`）：p' = sigmoid(a + b · logit(p))，每种起点一组，只在调参集上拟合：第 1 回合 (0.730, 0.498)，战中 (0.748, 0.864)，战前 (0.708, 0.519)。b < 1，说明模拟在两头过于自信。给绝对胜率时用映射后的数；配对差（`compareLines`）仍用原始样本算。

实盘不变的保证：新增的字段和开关只在 simulateFight 或模拟专用的选项下读取，实盘不设。tests/boss-sim.test.ts 用合成盘面算了一份实盘数字的摘要：solver 各线和 5 回合推演的估计。摘要在改动前（89b8cd0）和改动后逐字节相同，测试把它固定为常量。另有一个测试核对：推演会忽略 `fightRelics`，未设开关时 `policyWeights` 为空。

## 7. 已知偏差和限制

B1.5 之后的情况：

1. **原始胜率仍偏悲观、两头过于自信**。验证集第 1 回合起，原始预测平均胜率 0.533，实际 0.593；0–20% 那一桶实际赢了 19%。要用绝对胜率，用 `calibratedWinProb`（Platt 映射，只在调参集上拟合）。比较两条线或两副牌组时，用原始样本的配对差（`compareLines`）。
2. **跨回合漂移**（§6.2）：单回合出牌对得上，打几回合以后局面比实际差。原因包括：
   - 没建模的随机药水，实际每场多喝约 0.3 瓶；
   - 没建模的遗物：Orichalcum、Pendulum、Ice Cream、Ripple Basin、Sturdy Clamp、Pael's Tears 各出现在 8–13 场里；
   - 一回合策略看不到后面几回合。
   
   偏防守的选择（格挡牌、稳的线）仍可能被低估。
3. **按 boss 的偏差**：
   - 帝王蟹被打穿 1.6 倍，背后攻击没建模，策略也挡得少；
   - 实验体 2.5 倍，只有 9 场；
   - 女王 1.1 倍；
   - 贪得无厌者偏乐观，伤害多约 17%；
   - 幻影墨和知识恶魔伤害偏低。
4. 战前起点的敌人和遗物取自日志的第 1 回合状态。B3 在地图、奖励、商店里没有战斗状态，还要从 monster-db 和遗物表建开场（§8）。
5. 已知抽牌略乐观；知识恶魔 Ponder 和诅咒的次数上限、战斗中途起点时 Pressure Gun 已用次数，这几项没建模。
6. 验证集以 A9 为主（60/141），调参集几乎全是 A7/A8，第 5 回合起的 Brier 在验证集上没有改善（0.096 → 0.099 原始，0.094 校准）。每个 boss 的场次都少：第三幕验证集只有 14 场。
7. 在「推演」「推演-模型」对比里，fight-value 模型对 312 场是样本内的（B1 的 §5）。

## 8. 给 B2 / B3 的接口建议

Dai 2026-09-30 定的前提：

- 架构不变。boss 战里仍由 Jev 每回合从几条线里挑一条出牌；整场模拟只提供每条线「照这样打完整场」的数字和整场计划，代码不直接按计划出牌。
- 时间预算：boss 战每回合可以多花 20–30 秒，构筑类问题每题可以多花 10–15 秒。

### B1.5 之后能不能接

- **B3（构筑按模拟打本幕 boss）可以开始接**。战前起点在验证集上，校准后 Brier 0.146，各桶误差都在 4 个百分点内；配对比较在关键检查上方向对：同族场去掉唯一的群伤牌，胜率掉 35 个百分点。
  - 还缺一块 `syntheticBossStart`：构筑题没有战斗状态，要从牌组、遗物、药水、进场血量和 boss id 建开场。敌人的血量、第一招和首见能力按 monster-db 取；我方遗物对第 1 回合的影响（能量、格挡、抽牌）要按遗物表加。现在的战前起点借用了日志里第 1 回合的状态。
  - 给 DeepSeek 的数要同时有胜率差 ± 标准误和掉血差；校准后胜率低于 10% 的牌组，配对差没有信息，要注明。
- **B2（boss 战整场规划）可以作为信息接**：给每条线的胜率、掉血和配对差，Jev 仍然自己选线。
  - 30 个局面里 Jev 选的线 24 个和最优线并列，比较的耗时在预算内。
  - 帝王蟹、实验体、女王这三个 boss，模拟被打穿的血是实际的 1.1–2.5 倍，这几场的数要标成低可信，或者不给。
  - 被打穿的血「10% 以内」的目标，只有第 1 回合起总体刚好达到（1.10）。第 5 回合起（B2 的起点类型）是 1.17。
  - 要在 B2 前补上的：随机药水（按 potion-mc 的方式进模拟）、上面几个遗物、帝王蟹的朝向。

### B2：boss 战整场规划

- **输入**：直接用实盘推演的输入（rollout-live 的 `boardRolloutInput` + 抽牌堆 / 弃牌堆 + `fightMetaOf`），不用另外建。
- **每条线怎么模拟**：Jev 这回合看到的每条线，加上「整场不喝药」那条线，一起交给 `runBestOrder((i, l, o) => pool.run(i, l, o), input, lines, { samples, seed })`：每个击杀顺序跑一次（同一组种子），每条线取最好的顺序，`byOrder` 留着每个顺序的数。tools/boss-sim/lines.ts 就是这样做的。
- **给 Jev 看什么**：
  - 每条线的胜率、掉血中位和 p90、赢时的回合数、死亡回合分布；
  - 和最好那条线的配对差（`compareLines`：胜率差 ± 标准误），差距在 2 个标准误以内的线就说「并列」；
  - 整场计划：取最好那条线的 `perTurn`（逐回合预期掉血和伤害、第几回合前已赢 / 已死的比例），加上药水在多少样本里喝了。还需要补一项：记录喝药在第几回合，现在只记了喝没喝。
- **样本数和并行数**：24 个 worker 时，一条线 300 样本中位 0.3 秒、最慢 1 秒。按每回合 20–30 秒的预算，建议**每回合最多 10 条线 × 600 样本**（约 6000 个样本，中位约 3–4 秒，最慢约 10–15 秒）。600 样本时，两条线胜率配对差的标准误约 1–2%。池在战斗开始时建好（0.4 秒），整场复用；worker 最多 24 个，给对局留核。再给 runNow 加一个截止时间，超时就按已经跑完的块出数，和推演的降级一样。
- **策略偏差**（B1.5 §6.2）：单回合出牌已经和实际对得上。整场的偏差来自跨回合漂移，靠调策略的防守修不好：试过更防守的权重，整场被打穿的血降下来了，但胜负预测反而变差。接下来的方向是补齐没建模的资源（随机药水、遗物），以及做 boss 专门的机制（帝王蟹的朝向）。「给策略看下回合意图」只影响 solver 的平静回合自伤和覆甲这两项，B1.5 没有做。

### B3：构筑按模拟打 boss 的结果判断

- **缺的一块：合成 boss 开场**。构筑问题发生在地图、奖励、商店里，没有战斗状态，需要一个 `syntheticBossStart(deck, relics, potions, entryHp, bossId, asc)`。B1.5 已经有了模拟器这一侧：`redealInput` 和不给线的起点回合；这里缺的是从状态外建盘面：
  - 抽牌堆 = 牌组洗牌，手牌为空；
  - 敌人的 EnemySim 和出招表按 monster-db 取（进阶血量、第一招、首见能力如 Asleep / Plating / Artifact / Slippery）；
  - 进场血量用路线投影的预计值。
  
  模拟器这边的改动 B1.5 已经做了：`simulateFight` 的 line 传 null，`options.drawFirst` 设抽几张。
- **对比方式**：K 个选项（拿哪张牌、跳过、删牌、升级），每个选项一副牌组，用同一个种子各跑一次，按样本序号配对（`compareLines`）。敌人出招流按敌人位置定，和牌组无关，所以各选项看到的 boss 出招一模一样。牌组大小不同时洗牌结果会不同，这部分噪声靠样本数压下去。
- **样本数**：每题 10–15 秒的预算，建议**每个选项 1000 样本、最多 5 个选项**（约 5000 个样本，24 个 worker 下约 3–6 秒）。胜率配对差的标准误约 1–1.5%，差距小于 2 个标准误就报「没区别」。本幕 boss 已知（run.boss_id），只模拟这一个。也可以同时报后面几幕的 boss，但离得越远，牌组还会变，意义越小。
- **注意**：格挡牌、防守能力牌的价值可能被低估（§6.2 的跨回合漂移）。B3 给 DeepSeek 的数最好同时有胜率差和掉血差，并注明这一偏差。另外，模拟判为几乎必输的牌组上，配对差没有信息（§6.6）。
