## 1. 用法

```ts
import { BossSimPool, calibratedWinProb, compareLines, redealInput, runBestOrder, runBossSim } from "../sim/boss-sim.js";

// input: RolloutInput，和 5 回合推演用的同一个（rollout-live boardRolloutInput + 抽牌堆/弃牌堆 + meta）
const serial = runBossSim(input, [lineA, lineB], { samples: 300, seed: 1 });   // 单线程
const pool = new BossSimPool();                                               // 默认核数 − 4，最多 24
const res = await pool.run(input, [lineA, lineB], { samples: 300, seed: 1 }); // 数和 serial 完全一样
const diff = compareLines(res.lines[0]!, res.lines[1]!);                      // 配对差：胜率差 ± 标准误
await pool.close();

// B1.5
runBossSim(input, [null], opts);                                              // 不给线：起点回合也由策略出
const pre = redealInput(input, { fresh: true, hp: entryHp });                 // 战前起点：牌组洗牌、手牌空、进场血量
const best = await runBestOrder((i, l, o) => pool.run(i, l, o), input, lines, opts); // 每条线取最好的击杀顺序
calibratedWinProb(best.lines[0]!.winProb, 300, "mid");                        // 绝对胜率用 Platt 映射（start / mid / pre）
```

每条线的输出（`BossSimLineResult`）包括：

- 胜率，以及赢 / 死 / 到上限各多少样本；
- 掉血分布：全部样本一起算（死了算全部血量加复活的血量）；赢的样本另算一份；每份给均值、中位、p25、p75、p90、最小、最大；
- 回合数分布（全部样本 / 只算赢的样本）；
- 死亡回合，按回合计数，另给分布；
- 每种药水有多少样本喝了；
- 没赢的样本里敌人平均还剩多少血；
- 逐回合数据：还在打的样本数，平均掉血、伤害、来袭、被打穿的血，到这回合末还活着 / 已赢的样本数；
- 每个样本的结果（按样本序号排）。

回测工具在 tools/boss-sim/：

- `extract.py`：从日志库取 boss 战，按偏移读 states.jsonl 的开场局面和第 5 回合局面；
- `backtest.ts`：逐场跑模拟、5 回合推演、boss 时钟，可分片并行；
- `report.py`：出报告；
- `bench.ts`：测速度；
- `trace.ts`：单场单样本逐回合对照日志，调试用；
- `backtest-board.ts`：把日志状态按实盘规划器的方式还原成盘面。

复现命令见 §9。

## 2. 设计

**完全复用推演**。每个样本都跑 src/strategy/rollout.ts 里的 `simulate`，只是入口换成新导出的 `simulateFight(input, line, maxTurns, seed)`。推演原有的这些机制全部照用，不另写一套卡牌或怪物规则：

- 抽牌堆洗牌和抽牌，弃牌堆洗回；
- 怪物按出招模型（move-model 的后继计数）出招，伤害按 monster-db 的按进阶数值，另外处理力量、易伤、虚弱、格挡、覆甲、各种自身增益、状态牌、给我方上的减益；
- 我方的持续能力（恶魔形态、燃烧、金属化……）、遗物能量和格挡、复活；
- 药水：手里建了模的药水当作 0 费、只能用一次的牌，带 potion-cost 的代价；boss 战代价为 0，solver 觉得有用就喝；
- 召唤（死亡时生成）、幻象复活、分段重连、瀑布巨兽的空壳爆炸、实验体换阶段、沙坑。

每回合的出牌由 turn-solver 决定，节点上限 1500；实际平均每回合只用约 47 个节点，上限基本碰不到。

和推演不同的地方有四点：

1. **没有窗口**，一直打到 boss 死或我方死。上限 30 回合（日志里 boss 战最长 24 回合），到上限记为「未分胜负」（capped），不算赢。回测里一次都没碰到上限。
2. **没有终值估计，也没有时间预算**。每个样本只由（输入、线、种子）决定。
3. **整场脚本**（`fullFight`）。只在整场模拟里打开，5 回合推演里全部关闭。在同样 62 个日志局面上核对过，推演输出和改动前 aba384c 逐字节相同。长时间模拟会暴露一些出招模型的问题，这里逐个补上：
   - 出招模型的后继计数里混着「死了 / 换阶段那回合」的转移，比如巨兽每招后有约 10% 接 EXPLODE。整场模拟里，活着的敌人不会用死亡招式（`DEATH_MOVES`），也不会用别的阶段的招式（`PHASE_MOVES`，实验体三个阶段各用自己的招式，新阶段从第一招开始）。
   - 仪式兽：Plow 阈值（A8 150、A9 160）第 2 回合才出现，按 monster-db 的首见回合补上（`shriekFrom`）。阈值没打穿之前一直用 Plow，打穿时被击晕、当回合出招作废，之后进入 Beast Cry 循环。
   - 女王：火炬头活着时一直用 Burn Bright For Me，火炬头死后转 Off With Your Head。这是日志 15 场全部如此归纳出来的。
   - 乐加维林族母：Asleep 3 回合；第一次掉血就醒，当回合眩晕、下回合 Slash；醒来时覆甲和格挡清零（日志：睡着时格挡 12/12/11，第 4 回合为 0）。
   - 越打越强的招式：实验体 Multi Claw 每用一次加一段（10×3、10×4……）；巨兽 Pressure Gun 每用一次加 5（A8 20/25/30，`growth` 取自 monster-db 的 moveBaseDamages）。
   - **每个敌人用自己的随机流选招**：种子由样本序号和敌人在场上的位置决定。这样两条线在同一个样本里看到的敌人出招相同（common random numbers），和我方怎么抽牌、打哪条线无关。
   - **抽牌抽到的牌能打出去**（`knownDraws`）。推演里抽牌牌抽到的牌直接进弃牌堆，用处只在 solver 的分数里记一个固定值，所以每回合实际少打约 0.8 张牌；日志里 boss 战牌组平均 23.5 张，其中 3.5 张会抽牌。整场模拟把抽牌堆顶上的牌作为已知的 `drawn` 交给 solver，代替期望值的抽牌，对应实盘「抽完牌重新规划」。代价是策略提前知道会抽到什么，略偏乐观。
4. **策略的伤害权重乘 0.5**（`BOSS_SIM_DAMAGE_SCALE`，通过 turn-solver 新增的 `SolverInput.damageScale` 实现，实盘不设）。日志里的 boss 战比 solver 的最优线挡得多，见 §5.4。依次试了 1、0.7、0.5、0.3，0.5 的 Brier 最好。B1 是在全部场次上选的，属于样本内；B1.5 只在调参集上重选，结果仍是 0.5（§6.4）。
5. **B1.5 的几处改动**（§6.3）：
   - 起点回合可以不给线，由策略出；
   - 战前起点 `redealInput`；
   - 回合遗物 `fightRelics`；
   - 喝药要付 0.5 × 药水表的 holdHp（`potionHold`）；
   - 每条线取最好的击杀顺序 `runBestOrder`；
   - HP 权重和威胁项做成开关（`hpScale` / `threat`，默认关）；
   - 绝对胜率用 Platt 映射 `calibratedWinProb`。

**Common random numbers**：样本 i 的种子是 `sampleSeed(seed, i)`，和是哪条线、哪副牌组无关，所以比较两条线（B2）或加不加一张牌（B3）时，两边第 i 个样本用同一个种子。`compareLines` 按样本序号给出配对差和标准误。测试核对了三点：同一条线跑两遍逐样本相同；两条不同的线在双方都还在打的回合里，敌人出招序列相同；并行结果和串行完全一致。

**并行**：`BossSimPool` 把（线、样本）任务切成小块，谁空闲就发给谁。worker 是 TypeScript，经 tsx 载入；在 vitest 里也能用。worker 启动一次约 0.44 秒，一个进程里建一个池反复用即可。每个任务只由输入和种子决定，所以池的结果和 `runBossSim` 串行结果逐样本相同，有测试核对。

**对实盘的改动**：只有三处，都不改变实盘行为。

- rollout.ts 多了 `fullFight` 分支和 `simulateFight` 导出。
- turn-solver 多了可选的 `damageScale` 字段，实盘不设。
- rollout-live 的 `enemyTable` 多带两个字段 `growth` 和 `shriekFrom`，只有整场模拟会读。
- B1.5：
  - turn-solver 多了可选的 `hpScale`，实盘不设；
  - rollout.ts 的 `simulate` 允许不给起点线（只有 simulateFight 会传 null），新增 `RolloutInput.fightRelics`，只在 `fullFight` 里读；
  - `policyWeights` 在没设模拟开关时返回空，和原来的 `damageScale` 分支等价；
  - rollout-live 新增 `fightRelicsOf`，实盘不调用。
  
  tests/boss-sim.test.ts 在合成盘面上用 solver 和 5 回合推演的数字做了一份摘要。这份摘要和改动前（89b8cd0）逐字节相同，测试把它固定为常量。

src/sim/ 在 B1、B1.5 里不被 src 里任何别的模块引用。B2 起 combat-plan.ts 经 src/sim/boss-lines.ts 引用（§11）；B3 起 src/loop.ts 引用 build-sim-facts（构筑题的事实），src/index.ts 引用 build-sim-pool（整局一个 worker 池）（§12）。tests/rollout.test.ts 检查这一点。

## 5. 回测

口径：用 tools/boss-sim/extract.py 取日志库 fights 视图里 room = boss 的战斗，A7–A9 共 424 场（2026-09-26 至 09-30）。起点有两个：

- 第 1 回合第一个决策帧。不用 observed 帧，因为 164 场的第一帧是在抽牌之前记的，手里没牌。
- 第 5 回合第一个决策帧（打到第 5 回合的 412 场）。

实际结果：

- 战斗结束血量 = min(最后一个战斗帧, 战后第一帧)，死了记 0，同 docs/eval.md §7.2；
- 掉血 = 起点血量 − 结束血量；
- 回合数 = 从起点那回合算起。

有 2 场的第 1 回合规划器没调用 solver，算不了，所以第 1 回合起是 422 场。

对比对象都在同一个状态上离线重算：

- **推演**：rolloutDecision，线上的设置（5 回合 × 8 样本、门控终值，这里不限时），取同一条线的「到战斗结束的预期掉血 / 胜率」；
- **推演-模型**：同一推演换成 fight-value 模型终值（w = 1）。这个模型是在这些战斗上训练的，所以全集上的数是样本内的，偏乐观；**留出集**只算模型训练行（.cache/fight-value-rows.jsonl，324 局）里没有的局，共 112 场 boss 战；
- **时钟**：boss-clock.ts 按实际进场血量重算，只有第 1 回合。时钟不给概率，胜负预测按「够」（gap 0）算 1、否则 0；AUC 用 −gap 算；赢局掉血 = 每回合掉血 × 时钟回合数。

误差一律是 预测 − 实际。

### 5.4 偏差：出在哪里

偏差最大的三个 boss 和原因：

- **帝王蟹**：来袭和伤害都对，但模拟每回合多被打穿 6.5 血，是所有 boss 里差得最多的。solver 在这一场有专门的「两只钳子血量平衡」项，加上伤害优先，线都偏进攻；实际对局每回合挡得多（第一回合的例子：solver 最优线掉 18，Jev 选的线掉 1）。后续回合的背后攻击没建模，模拟里的来袭本该更高，所以算上它模拟会更悲观。原因属于**策略打得比实际差**。
- **女王**：模拟的伤害比实际低 18%（35 对 43），多被打穿 5.8 血。不给击杀顺序时伤害更低（29 对 43）：solver 打 minion 打折，不去打火炬头，火炬头一直活着。给了「先杀火炬头」之后，打穿的血仍然多。原因是**策略**（You Are Mine 之后一直虚弱加脆弱，挡的效率低，实际对局靠的是牌组里的大格挡牌加药水），另外火炬头招式用的是显示值，属于**怪物模型的近似**。
- **实验体**：第二阶段的 Multi Claw 每回合多一段，模拟被打穿 29.6，实际 12.6。实际对局在第二阶段几乎全力防守，solver 的一回合策略看不到「下回合多一段」，照常进攻。原因是**策略看不到后续回合**。只有 9 场。

另外：

- 幻影墨和知识恶魔是**伤害偏低**：幻影墨有 Slippery，实际对局会用多段攻击去剥层数；知识恶魔给 Sloth 后每回合最多 3 张，实际对局选大牌。
- 贪得无厌者是唯一偏乐观的 boss，模拟的伤害比实际高 23%。

| 伤害权重 ×0.5 | 6.52 | 26.0 |
| ×0.5，手牌从抽牌堆重新发 | 6.80 | 25.7 |

从真实局面出发，×0.5 的策略每回合并不比实际多掉血。按「来袭 / 当前血量」分段看（这一段和下面按 boss 的数用的是另一次回放，1496 个回合，实际每回合 6.60），×0.5 在来袭小的回合挡多了（< 0.2 段：3.45 对实际 4.55），在来袭大的回合挡少了（≥ 0.7 段：10.97 对 9.03）。换成「×1 + 威胁项 2」（HP 权重乘以 1 + 2 × 来袭 / 血量），各段都能对上：4.17 / 7.93 / 10.68 / 9.64，实际是 4.55 / 8.09 / 10.10 / 9.03。按 boss 看，×0.5 在帝王蟹（13.7 对 10.0）、女王（12.7 对 10.6）、永恒镜（12.1 对 8.8）挡少了；在幻影墨（3.3 对 5.6）、仪式兽（4.7 对 6.1）挡多了。验证集上每回合的差更大一些：×0.5 掉 8.73，实际 7.55。

**同一批回合，整场模拟打过来是多少**：还是 ×0.5 的策略（调参阶段「策略起手 ×0.5」的配置），但从第 1 回合一路模拟到这一回合，逐回合的掉血和单回合回放、实际放在一起比（调参集，都是 Jev 规划过的回合）：

| 回合 | 场 | 实际 | 单回合回放 | 整场模拟 |
|---|---|---|---|---|
| 2 | 208 | 8.2 | 8.0 | 9.7 |
| 3 | 203 | 7.9 | 7.8 | 10.7 |
| 4 | 158 | 6.1 | 7.2 | 8.9 |
| 5 | 160 | 7.9 | 6.8 | 10.2 |

所以多掉的血，大部分不是「这一回合的出牌偏进攻」，而是**模拟打过几个回合以后的局面比实际差**。逐个核对过的局面量：

- 能量：修之前，第 2 回合有 36/311 场比实际少 1–2 点。原因是烛台之类的回合遗物没建模，修后 3.22 对 3.25。
- 我方虚弱 / 易伤、力量、回合开始时的格挡：都接近，力量到第 7 回合落后约 0.7。
- 敌人来袭：逐个 boss 看均值、标准差和为 0 的比例，都对得上，只有实验体偏高（38.7 对 35.2）。
- 药水：修之前，策略在第 1 回合就喝掉约 80% 的药水，实际第 1 回合只喝 40%。而且实际每场比模拟多喝约 0.3 瓶，这部分是没建模的随机药水。

把策略调得更防守（×0.3、HP 权重 ×1.5、威胁项 1–2），整场模拟被打穿的血确实降下来了（第 5 回合起比值到 1.0），但战斗拖长，模拟胜率反而更低，Brier 变差（§6.4）。也就是说，「策略偏进攻」只能解释单回合里的一小部分差距；整场的偏差还来自跨回合的东西：没建模的药水和遗物，以及 Jev 靠推演做的跨回合安排（B2 的比较本身也要用到这一点）。

### 6.3 改了什么（只在整场模拟里生效）

1. **起点回合也由策略出**：`simulateFight(input, null, …)`，B1 用的是 solver 在实盘权重下的第一条线。B2 比较线时仍然传具体的线。
2. **回合遗物**：`RolloutInput.fightRelics`，由 rollout-live 的 `fightRelicsOf` 生成。包括烛台第 2 回合 +2 能量、吊灯第 3 回合 +3 能量、开心小花按计数每 3 回合 +1 能量、船夹板第 2 回合 14 格挡。数值取自日志：持有这些遗物的 boss 战分别有 22、15、42、13 场，拿它们和不持有的场次比回合开始时的能量和格挡。只有 `fullFight` 读这个字段。
3. **药水留着用**：策略每喝一瓶药，要付 0.5 × 药水表里这瓶药的 holdHp（`potionHold`，模拟专用，实盘 boss 战的药水代价仍是 0）。
4. **击杀顺序取最好**：`fightOrders` / `runBestOrder`。每条线在「solver 自选目标」和每一种击杀顺序下各跑一次，用同一组种子，保留胜率最高的一种，和推演的做法一致。涉及帝王蟹、同族、女王。B1 只给女王固定了「先杀火炬头」。
5. **伤害权重 0.5** 在调参集上重选；HP 权重倍数（`hpScale`）和威胁项（`threat`，turn-solver 新增的 `SolverInput.hpScale`）做成开关，默认关。
6. **Platt 映射**（`BOSS_SIM_PLATT` / `calibratedWinProb`）：p' = sigmoid(a + b · logit(p))，每种起点一组，只在调参集上拟合：第 1 回合 (0.730, 0.498)，战中 (0.748, 0.864)，战前 (0.708, 0.519)。b < 1，说明模拟在两头过于自信。给绝对胜率时用映射后的数；配对差（`compareLines`）仍用原始样本算。

实盘不变的保证：新增的字段和开关只在 simulateFight 或模拟专用的选项下读取，实盘不设。tests/boss-sim.test.ts 用合成盘面算了一份实盘数字的摘要：solver 各线和 5 回合推演的估计。摘要在改动前（89b8cd0）和改动后逐字节相同，测试把它固定为常量。另有一个测试核对：推演会忽略 `fightRelics`，未设开关时 `policyWeights` 为空。

### 6.7 候选线比较（B2 的底座）

tools/boss-sim/lines.ts，结果在 b15-lines.jsonl。从验证集里抽 30 个战中局面：第 2–8 回合，12 个 boss 都有，每场只取一个回合。每个局面比较 solver 的前 5 条线、Jev 实际选的线和模拟策略自己的线。每条线 300 个样本，用同一组种子，击杀顺序取最好。

- **Jev 实际选的线排第几**：在参与比较的线里（平均 5.2 条），11/30 排第 1；排名分布为第 1 名 11 次、第 2 名 5 次、第 3 名 5 次、第 4 名 3 次、第 5 名 4 次、第 6 名 2 次。24/30 和最优线的差在 2 个标准误以内，算并列。
- **和最优线差多少**：胜率差中位 0，平均 −2.6 个百分点。差距超过 5 个百分点的有 4 个局面：
  - 同族 YX5E7NFW5R82:7 第 4 回合：−20.7 ± 2.4。Jev 集火神官；模拟认为先打完 2 号信徒更好，这回合 0 掉血，胜率 99%。
  - 幻影墨 ZY3992X5VEVS:7 第 3 回合：−19.3 ± 3.0。Jev 没出闪电霹雳。
  - 同族 ZGZ0EQDDNJPT:7 第 2 回合：−17.3 ± 2.6。
  - 帝王蟹 VCM94LZR1DTA:15 第 2 回合：−6.0 ± 2.0。
- solver 自己的第 1 条线在 20/30 个局面里是模拟的最优。模拟策略自己的线平均比最优线低 1.7 个百分点。
- **耗时**（24 个 worker，每条线 300 样本，再乘上击杀顺序数）：每个局面中位 1.3 秒，最慢 21 秒。最慢的是同族局面：7 条线 × 3 种击杀顺序。在每回合 20–30 秒的预算内，但同族、帝王蟹这类多敌人的场，要么把样本减到 200，要么只跑 Jev 看到的线。

## 7. 已知偏差和限制

B1.5 之后的情况：

1. **原始胜率仍偏悲观、两头过于自信**。验证集第 1 回合起，原始预测平均胜率 0.533，实际 0.593；0–20% 那一桶实际赢了 19%。要用绝对胜率，用 `calibratedWinProb`（Platt 映射，只在调参集上拟合）。比较两条线或两副牌组时，用原始样本的配对差（`compareLines`）。
2. **跨回合漂移**（§6.2）：单回合出牌对得上，打几回合以后局面比实际差。原因包括：
   - 没建模的随机药水，实际每场多喝约 0.3 瓶；
   - 没建模的遗物：Orichalcum、Pendulum、Ice Cream、Ripple Basin、Sturdy Clamp、Pael's Tears 各出现在 8–13 场里；
   - 一回合策略看不到后面几回合。
   
   偏防守的选择（格挡牌、稳的线）仍可能被低估。
3. **按 boss 的偏差**：
   - 帝王蟹被打穿 1.6 倍，背后攻击没建模，策略也挡得少；
   - 实验体 2.5 倍，只有 9 场；
   - 女王 1.1 倍；
   - 贪得无厌者偏乐观，伤害多约 17%；
   - 幻影墨和知识恶魔伤害偏低。
4. 战前起点的敌人和遗物取自日志的第 1 回合状态。B3 在地图、奖励、商店里没有战斗状态，还要从 monster-db 和遗物表建开场（§8）。

### B2：boss 战整场规划

- **输入**：直接用实盘推演的输入（rollout-live 的 `boardRolloutInput` + 抽牌堆 / 弃牌堆 + `fightMetaOf`），不用另外建。
- **每条线怎么模拟**：Jev 这回合看到的每条线，加上「整场不喝药」那条线，一起交给 `runBestOrder((i, l, o) => pool.run(i, l, o), input, lines, { samples, seed })`：每个击杀顺序跑一次（同一组种子），每条线取最好的顺序，`byOrder` 留着每个顺序的数。tools/boss-sim/lines.ts 就是这样做的。
- **给 Jev 看什么**：
  - 每条线的胜率、掉血中位和 p90、赢时的回合数、死亡回合分布；
  - 和最好那条线的配对差（`compareLines`：胜率差 ± 标准误），差距在 2 个标准误以内的线就说「并列」；
  - 整场计划：取最好那条线的 `perTurn`（逐回合预期掉血和伤害、第几回合前已赢 / 已死的比例），加上药水在多少样本里喝了。还需要补一项：记录喝药在第几回合，现在只记了喝没喝。
- **样本数和并行数**：24 个 worker 时，一条线 300 样本中位 0.3 秒、最慢 1 秒。按每回合 20–30 秒的预算，建议**每回合最多 10 条线 × 600 样本**（约 6000 个样本，中位约 3–4 秒，最慢约 10–15 秒）。600 样本时，两条线胜率配对差的标准误约 1–2%。池在战斗开始时建好（0.4 秒），整场复用；worker 最多 24 个，给对局留核。再给 runNow 加一个截止时间，超时就按已经跑完的块出数，和推演的降级一样。
- **策略偏差**（B1.5 §6.2）：单回合出牌已经和实际对得上。整场的偏差来自跨回合漂移，靠调策略的防守修不好：试过更防守的权重，整场被打穿的血降下来了，但胜负预测反而变差。接下来的方向是补齐没建模的资源（随机药水、遗物），以及做 boss 专门的机制（帝王蟹的朝向）。「给策略看下回合意图」只影响 solver 的平静回合自伤和覆甲这两项，B1.5 没有做。

### B3：构筑按模拟打 boss 的结果判断

- **缺的一块：合成 boss 开场**。构筑问题发生在地图、奖励、商店里，没有战斗状态，需要一个 `syntheticBossStart(deck, relics, potions, entryHp, bossId, asc)`。B1.5 已经有了模拟器这一侧：`redealInput` 和不给线的起点回合；这里缺的是从状态外建盘面：
  - 抽牌堆 = 牌组洗牌，手牌为空；
  - 敌人的 EnemySim 和出招表按 monster-db 取（进阶血量、第一招、首见能力如 Asleep / Plating / Artifact / Slippery）；
  - 进场血量用路线投影的预计值。
  
  模拟器这边的改动 B1.5 已经做了：`simulateFight` 的 line 传 null，`options.drawFirst` 设抽几张。
- **对比方式**：K 个选项（拿哪张牌、跳过、删牌、升级），每个选项一副牌组，用同一个种子各跑一次，按样本序号配对（`compareLines`）。敌人出招流按敌人位置定，和牌组无关，所以各选项看到的 boss 出招一模一样。牌组大小不同时洗牌结果会不同，这部分噪声靠样本数压下去。
- **样本数**：每题 10–15 秒的预算，建议**每个选项 1000 样本、最多 5 个选项**（约 5000 个样本，24 个 worker 下约 3–6 秒）。胜率配对差的标准误约 1–1.5%，差距小于 2 个标准误就报「没区别」。本幕 boss 已知（run.boss_id），只模拟这一个。也可以同时报后面几幕的 boss，但离得越远，牌组还会变，意义越小。
- **注意**：格挡牌、防守能力牌的价值可能被低估（§6.2 的跨回合漂移）。B3 给 DeepSeek 的数最好同时有胜率差和掉血差，并注明这一偏差。另外，模拟判为几乎必输的牌组上，配对差没有信息（§6.6）。

B3 按上面的建议做了，见 §12。和建议不同的地方：击杀顺序只在当前牌组上选一次（每个牌组都跑三种顺序要花三倍时间），样本数按截止时间来，不固定 1000。

### 11.2 线的整场数字怎么接

- **什么时候跑**：boss 战、`BOSS_SIM_LINES` 开着，出题时（推演和随机药水蒙特卡洛之后）。要模拟的线 = 题面上的每条方案线（代码的选项，加上推演补的最优线；boss 战没有「本场不用药」线，这条线只在非 boss 战出现）+ 每瓶随机药水「喝了再重新规划」选项的中位样本线（和推演一样）。没有模拟效果的药水选项不给数字。
- **输入**：推演的输入（rollout-live 的 `boardRolloutInput`、`fightMetaOf`、抽牌堆 / 弃牌堆）+ 回合遗物 + 随机药水源（`bossSimInput`）；策略的设置同 B1.5（伤害权重 ×0.5、药水保留 0.5）。boss 战的药水代价仍是 0，排序里不算药水代价；药水保留只是模拟策略什么时候喝药的行为模型。
- **一次跑完**：每条线 ×（solver 自选目标 + 每种击杀顺序）作为一组，全部用同一组种子（common random numbers）；每条线取胜率最高的击杀顺序（同胜率取赢局掉血中位少的，和排序同一个口径；V4.2 前是平均掉血，同 `runBestOrder`）。
- **同步 worker 池**（`BossLinesPool`）：规划器是同步的，所以 worker 把结果发到各自的 MessagePort 后给一个共享计数器加 1，规划器线程用 `Atomics.wait` 等、用 `receiveMessageOnPort` 收。池在本场 boss 战第一次出题时建（默认 20 个 worker，V4.2 前是 12；`BOSS_SIM_WORKERS` 可改；最多核数 − 2、24 个），整场复用，到非 boss 战出题时释放；worker 已 unref，不挡进程退出。**和 B3 的池不同时占着 worker**（V4.2，src/sim/sim-pools.ts）：boss 战和构筑题不会同时跑，所以一个池起 worker 时先放掉另一个池的——boss 战第一次出题时 B3 的构筑池（最多 24 个 worker、各自加载了 solver）被释放，boss 战后第一道构筑题时 B2 的池被释放（原来要等到下一场非 boss 战），被释放的池下次用时重建（每个 worker 约 0.4 秒，并行）。B3 的池本来就不预热（第一道构筑题才起 worker）。某次出题一个样本都没拿到（池坏了）就重建，本场连续两次就关掉。
- **截止时间**：每题最多 25 秒，每回合所有出题合计最多 30 秒（抽牌后重新出题也算在内），剩不到 3 秒就不跑。到时间就停，worker 在样本之间检查任务是否还有效，放弃剩下的；只用所有线都跑完的样本（同一批样本），题面注明「412 of 600 samples (time limit)」。
- **每条线给什么**（选项的 `whole_fight_sim` 字段，英文和题面一致），例如：

  `win 62% (vs the best line −3 ± 2 pts, tied on win rate), HP lost when won median 18, ~6 turns to win (this one included); the losing samples die most often on T9 (dead in 35%); later turns kill Torch Head Amalgam > Queen; 600 samples`

  - 胜率是校准后的（Platt：第 1 回合用 start 映射，之后用 mid 映射）；
  - 和最好那条线的差是原始样本的配对差（百分点）± 标准误；
  - 赢局掉血中位；赢的样本还要几回合（含本回合）；
  - 输的样本最常死在第几回合（写成本场的绝对回合）；
  - 击杀顺序（多敌人时，这条线取的最好顺序）；样本数。
- 5 回合推演的数字（`rollout`、`rollout_turns` 等）照旧保留，作参考。题面 state 多一个 `whole_fight_sim` 说明怎么读这些数字、`rollout_best` 现在按什么排。
- **决策日志**：`boss_sim`：耗时、样本数、是否到截止时间、击杀顺序数、worker 数、boss、是否低可信、最优线和并列线的 key、按排序的全部 key、每条线的原始胜率 / 校准胜率 / 与最优线的差和标准误 / 平均掉血 / 赢局掉血中位 / 击杀顺序、整场计划。

### 11.3 排序和低可信

- **排序**（`rankLines`）：先找原始胜率最高的线；和它的配对胜率差在 2 个标准误以内的线算胜率并列；并列的线里**赢局掉血中位**（`wonLoss`，就是题面上的「HP lost when won median」；V4.2 前是全部样本的平均掉血，死了算全部血）最少的是最优线，一样时胜率高的优先；一个赢的样本都没有的线排在并列组最后。胜率和赢局掉血中位完全一样的几条线算并列，都不标 `rollout_best`，而是标 `rollout_tied`（说明改成「整场模拟的数字相同」：the same simulated win rate and HP lost when won）。决策日志 `boss_sim.ranked` 的顺序也按这个口径。这个最优线就是题面的 `rollout_best`，决策日志 `rollout.best` 也是它，所以 `rollout_best_chosen` 的含义在 boss 战里变成「Jev 选了整场模拟的最优线」；推演自己的最优线另记在 `boss_sim.rollout_own_best` / `rollout_own_tied`。
- **一致性**：
  - HP 护栏：除了原来的条件，不会把 Jev 的选择换成整场模拟里胜率比它低 2 个标准误以上的线（`simWinsLess`）；
  - 代码自己的回退线（Jev 没给可用答案时）：整场模拟排序下最好的不喝药线（规则「有不喝药的选项时回退线不喝药」不变），rationale 写明；和 `rollout_best` 是同一个 `rankLines`，所以也按赢局掉血中位；
  - HP 护栏只比整场胜率（`simWinsLess`），不看模拟的掉血，所以 V4.2 的口径变化不影响它；
  - 药水代价：boss 战为 0，排序不看药水代价；
  - 执行闸不受影响。
- **低可信 boss**（`LOW_TRUST_BOSSES`）：B2 时是帝王蟹、实验体、女王、知识恶魔、永恒镜、贪得无厌者，按当时已知的问题列的；B4 起改成按验证集成绩的固定标准算，名单和原因从 src/sim/boss-trust.json 读（§13.8），B4 时是帝王蟹、女王、无厌沙虫、瀑布巨兽、永世沙漏、实验体（知识恶魔已转可信），B5 起是女王、无厌沙虫、瀑布巨兽、永世沙漏、实验体（帝王蟹已转可信，§14.6）。这些 boss 的 `rollout_best`、并列、HP 护栏、回退线都按原来的 5 回合推演。**V4.2（Dai 2026-10-01）起，Jev 的题面里不再出现它们的整场数字和整场计划**（选项没有 `whole_fight_sim`，state 没有 `whole_fight_sim` / `whole_fight_plan`），题面、Jev 的视图、每个答案的处理和 `BOSS_SIM_LINES=off` 逐字节相同；模拟照跑，决策日志照样记 `boss_sim`（`low_trust: true`，每条线的数字和整场计划），留着以后校验。模拟没跑出结果时（时间用完、池坏了），按局面里的敌人认 boss（`lowTrustOfState`），低可信 boss 也不写「模拟不可用」。B3 的构筑题不变：低可信照样给数字、标明原因（§12.4）。

### 11.4 整场计划

开场（第 1 回合）和之后每 3 回合（第 4、7、10……回合）出题时，题面 state 多一个 `whole_fight_plan`：从最优线的样本里总结一句，只作信息。低可信 boss 不给（只进决策日志，§11.3）。

提炼方法（`fightPlanText`）：只看最优线**赢了的样本**（少于 10 个时用全部样本，并直说「多数样本赢不了」）；一个动作要至少一半样本都做才写进去（「多数样本共有」）。回合都写成本场的绝对回合。

- **能力牌**：每张能力牌在多少样本里打出、第一次打出的回合中位数；过半样本打出的按回合排，写「T1–T2 play Demon Form, Inflame」。
- **大招回合**：每个回合在还在打的样本里的平均来袭，高于全场各回合中位的 1.5 倍、且不少于当前血量的 1/4 和 10 点，算「打得最重」的回合（最多 3 个）；只写来袭，例如「T4, T7 the enemies hit hardest (incoming ~34, ~36)」。V4.2 起不写样本在这些回合的格挡中位（模拟的策略在大招回合挡得比实际少，B1.5 §6.2，「block ~0」会被 Jev 当成建议）。
- **击杀顺序**（多个敌人）：每个敌人被打死的回合中位（过半样本打死才写）。
- **药水**：过半样本喝的药水和喝的回合中位。
- **结束**：赢的样本结束回合的中位，「the boss dies ~T9 (median of 40 winning samples)」。

测试里的样例（第 3 回合开始的盘面）：`T3 play Inflame; T6, T9 the enemies hit hardest (incoming ~34, ~36); drink block potion ~T6; the boss dies ~T9 (median of 40 winning samples)`。

### 11.5 开关

`BOSS_SIM_LINES=on|off`，默认 on（`bossLinesOptions.enabled`）。off 时 boss 战的题面、Jev 的视图、每个答案的处理（排序、HP 护栏、回退线、决策日志）和 B2 之前逐字节相同；非 boss 战开着也逐字节相同。tests/boss-lines-planner.test.ts 用日志里的 5 个 boss 盘面（每个 Jev 视图开 / 关各一次）和 1 个非 boss 盘面锁住：摘要在接入前的规划器上算好写进测试，规划器读的知识数据（怪物库、出招模型）用测试里固定的裁剪版，别的知识文件一律当作不存在，所以知识数据每局刷新也不影响这个测试。

### 11.2 选项对比（src/sim/build-sim.ts、build-sim-pool.ts）

- 当前牌组和每个选项的牌组（或血量）一起跑，第 i 个样本在所有牌组里用同一个种子（common random numbers），按样本配对算差。
- 有击杀顺序可选的 boss（同族、女王、帝王蟹）：先用当前牌组在「自选目标」和每种顺序下各跑 100 个样本，取赢得最多的顺序，之后所有牌组都按它跑（每个牌组都跑所有顺序要三倍时间）。
- 任务按样本分块（8 个样本一块），先把一块样本在所有牌组上跑完再跑下一块；到截止时间就停，只用每个牌组都跑完的样本，题面写明样本数（「目标 1000，到时间只跑完这些」）。
- 每个选项给：校准后胜率（B1.5 的 pre 映射，0 和 1 按 200 个样本收半个样本，和拟合时一致：0 胜的牌组读约 8%）；和当前牌组的差 = 两个校准胜率之差，± = 原始配对标准误 × 映射在两点间的斜率；赢局掉血中位；赢局回合数中位。当前牌组原始胜率低于 10% 时，胜率的差没有信息，另给 **boss 平均剩血**（赢的样本算 0）和它的配对差。
- worker 池（BuildSimPool，默认核数 − 4、最多 24 个）整个对局只建一次，第一道构筑题时启动；和 B2 的 BossSimPool 分开（各自的 worker 文件，互不影响）。V4.2：B2 的池起 worker 时（boss 战第一次出题）这个池的 worker 被释放，下一道构筑题再起，反过来也一样，两边不会同时有一堆空闲 worker（§11.2）。

各类构筑题怎么换算：

| 题 | 选项 | 换算 |
|---|---|---|
| 选牌 | 每张牌 | 牌组加这张（奖励里的数值） |
| | 跳过 | 当前牌组 |
| 商店 | 卡牌 | 牌组加这张；现在的金币买不起的不模拟 |
| | 删牌 | 每张能删的牌（永恒不算）各一行，放在 boss_sim_by_card |
| | 遗物 | 开场遗物表里的、或规划器 / 模拟会读的遗物：加上后重建开场；其余「效果没有建模：不模拟」 |
| | 药水 | 有空栏、且模拟里有这瓶药：加进药水栏；栏满或随机药水不模拟 |
| | 丢药水 | 重建开场时去掉这瓶 |
| 休息点 | 回血 | 按回血后的 HP 沿路线投影进场血量（休息点自己的回血文字，含遗物加成） |
| | 锻造某张 | 这张升级（card-upgrades.json 的数值；没有记录的注明按未升级算） |
| | 举重 | 壶铃多一层 |
| 选牌屏 | 升级 / 删牌 / 加牌 | 同上 |
| | 变化 | 删掉这张，加一张本角色的随机牌：取 6 张（按局面定种子），每张各占 1/6 的样本，结果是期望；题面写明是哪 6 张 |
| | 附魔 | 不模拟（附魔的战斗效果没有建模） |
| 事件 | 加减牌、升级、变化 | 选项文字里的「将 N 张 X 加入你的牌组」，以及选项要选的牌（o1:c5）：同上 |
| | 改血量 | 失去 / 受到 N 点伤害、回复 N 点生命、最大生命增减：按新 HP 沿路线投影 |

效果没有建模的牌（card-model 的 known = false，如地狱之刃、狂怒、添柴）加进或删掉时，行尾注明「作用可能被低估」。

### 11.6 耗时和验收（experiments/boss-sim-build/summary.md）

从日志取 20 道真实构筑题（experiments/build-facts-m2/targets.jsonl：选牌 4、商店 4、休息 4、事件 4、选牌屏 4），在决策时的状态上离线重出题并跑模拟（tools/boss-sim/build-replay.ts；不调用 DeepSeek）。12 个 worker，机器负载 3–16（别的 agent 和对局在跑），截止时间 11 秒：

- 19 道在范围内（附魔选牌屏不在）。每题用时中位 8.5 秒，最慢 11.0 秒；8 道到截止时间。每个选项的样本数最少 296（无厌沙虫商店，7 个选项；一场 83 毫秒）和 448（帝王蟹选牌，一场 55–69 毫秒，每回合求解 443 个节点）。其他 boss 一场 10–13 毫秒。上线时 24 个 worker、负载低，样本数大约翻倍。
- 题面每题多约 1.4k 字（最多 2.6k）。

**发现**：

- **当前牌组多半打不过时，胜率的差没有信息**：8/19 道题原始胜率 0（第 2–8 层的题、帝王蟹、第 20 层 53 血打无厌沙虫、知识恶魔、第 15 层的瀑布巨兽），所有选项的胜率差都是 0。boss 平均剩血能分出高低（例如删飞剑回旋镖 +17 血，买力量药水 −53 血）。离 boss 还远时，现在的牌组不是到 boss 时的牌组，这是这种比较本身的限制。
- **力量来源的影响很大**：仪式兽商店里删燃烧 −52.6、删痛击 −24.9；事件里把恶魔形态+ 变成随机牌 −63；燃烧+ 换成愧疚 −38。方向合理，量级可能被放大（模拟的战斗比实际更确定）。
- **格挡牌**：升级防御的价值不低（墨影幻灵 +11.2 和 +7.1，比升级打击 +2.1 高；另一局升级防御 +5.7、打击 +3.2）。但在伤害比拼型的 boss 上，加纯格挡牌是负的：仪式兽商店买岩石铠甲 −9.0，删防御 +8.7（删打击 +7.7）；无厌沙虫商店买耸肩无视 +0.5、火焰屏障 −0.7。这和 B1.5 说的「策略跨回合的防守不如实际」一致，是局限，已写进 facts.act_boss_sim.limits。
- **不加伤害的牌被当成稀释**：自动化 −10.7、武装 −8.0、挑衅 −4.2（仪式兽）。自动化这类效果没有完全建模的牌会注明。
- **血量**：第 11 层 38 血的休息点，回血 +45.4，锻造 +0.3 到 +10.5；到 boss 前还有休息点时回血差为 0。
- **药水**：火焰药水 +16.4、鲜血药水 +12.9；丢一瓶可用的药 −5 到 −7。

### 11.7 局限和待定

- 模拟的战斗比实际更确定：单张牌的差可能被放大；校准只把绝对胜率拉准，不校准差值。
- 格挡牌和防守能力牌仍可能被低估（B1.5 §6.2 的跨回合漂移）；帝王蟹、女王、实验体的偏差最大，已标低可信。
- 离 boss 远（幕初）时比的是现在的牌组，信息少；是否改成「本幕精英」或「只在离 boss ≤ N 层时给」需要 Dai 定。
- A10 双 boss：state 里只有 `run.boss_id`，第二个 boss 的身份拿不到（地图只标节点）；现在只算第一个。拿到身份后可以用第一个 boss 赢局掉血中位推第二个的进场血量。
- 开场遗物表只有日志里核对过的 20 来件；风箱（开场手牌升级）、烘焙手套（开场消耗）、开场伤害类遗物没建模，列在 relics_not_modelled。
- 事件的换算只认得「失去 / 受到 / 回复 N 点生命」「最大生命」「将 N 张 X 加入你的牌组」和选牌的后续；金币、遗物、随机结果的选项不模拟。
- 商店里买两件东西的组合不算（每个选项单独和当前牌组比）。
- 慢的 boss（无厌沙虫、帝王蟹）在大商店上样本少（几百个），标准误 1–2 个百分点；可以考虑只给买得起的前几件，或把 policyNodes 降到 300（会改变校准，要重测）。

### 13.2 帝王蟹（碾碎爪 + 火箭）

**核对**（日志 40 场）：两只钳子各自固定 5 招循环。碾碎爪：Thrash 12 → Enlarging Strike 4 → Bug Sting 6×2（虚弱、脆弱各 2）→ Adapt（+2 力量，A9 +3）→ Guarded Strike 12（18 格挡）；火箭：Targeting Reticle 3 → Precision Beam 18 → Charge Up（+2 力量）→ Laser 31 → Recharge。（数字是 A8 的基础伤害，面对时就是这个数，背对 ×1.5。）一只死了另一只 Crab Rage（99 格挡、+6 力量，CWU9BG62JE50 第 12 回合：96 格挡、力量 4 → 10）。这些模拟里都对。

**差在哪**：背后攻击算了两次。monster-db 给这类招式的伤害是「基础 × (1 + 0.5 × 记录里在背后的比例)」——这是给不跟踪朝向的 5 回合推演用的平均数（A8 Laser：基础 31，表里 42）。B2 给整场模拟加了朝向以后，又把背对的钳子 ×1.5：背后的 Laser 变成 63（日志 49），面对的 42（日志 33）。验证集第 1 回合起，模拟第 2 回合来袭 40.4（日志 30.2），第 4 回合 66.9（日志 44.9）。这也是 B2 补朝向后帝王蟹 Brier 反而变差的原因（§11.1）。

**修（分支 v4-sim-crabqueen，没有合进 v4-sim）**：`EnemyMove.faceDamage`（monster-db `moveDamageAt` 的 base），整场模拟在知道朝向时用它，面对的照基础，背对的 ×1.5；不知道朝向时仍用平均数。修后来袭对上了：第 2 回合 30.5 / 30.2，第 4 回合 49.4 / 44.9；第 2 回合打穿 24.4 → 17.7（日志 12.7），第 4 回合 41.4 → 29.5（日志 22.5）。

剩下的差在策略：同样的来袭下模拟挡得少、打得多（第 7 回合敌人剩血 161，日志 208）。见 §13.6。

### 13.3 女王 + 火炬头聚合体

**核对**（A7–A8 29 场，每回合从状态里读力量、易伤、虚弱）：

- 女王：Puppet Strings（锁链 3：每回合先抽的 3 张魂缚，打一张其余锁住——日志 104 个回合里 95 个只打了一张魂缚牌，模拟这样建的，对）→ You Are Mine（易伤、虚弱、脆弱各 99）→ 火炬头活着时一直 Burn Bright For Me（20 格挡）→ 火炬头死后 Off With Your Head → Execution → Enrage（+2 力量）循环。
- 火炬头：Strong Tackle 26 → Tackle 2 18 → Beam → Tackle 3 → Tackle 4 → Beam …（第 3 回合起三招循环）。

**差在哪**：

1. 火炬头的 Beam、Tackle 3、Tackle 4 和女王的 Off With Your Head、Execution 在 monster-db 里只有显示值（日志里每个回合都带着易伤 99），模拟按固定的显示值打，不加力量。用「显示值 = ⌊(基础 + 力量) × 1.5（我方易伤）× 0.75（它虚弱时）⌋」逐个观测反解，每一招所有观测都落在同一个基础上：Beam 8×3（24 次）、Tackle 3 14（16 次）、Tackle 4 14（14 次）、Off With Your Head 3×5（11 次）、Execution 15（5 次），A7 相同。
2. **Burn Bright For Me 每次给火炬头 +1 力量**（火炬头第 3 回合以后的回合，41 次里 36 次 +1；第 1–2 回合女王放 Puppet Strings / You Are Mine 时是 0）；**火炬头死时女王 +2 力量**（11 次里 9 次）。模拟两样都没有，Beam 一直是 12×3，日志第 6 回合是 16×3、第 9 回合 21×3。
3. 火炬头在 You Are Mine 那回合就被打死时，女王下回合直接 Off With Your Head（5GKAR00L5AYV:22 第 3 回合），模拟会先空放一回合 Burn Bright。

**修（分支 v4-sim-crabqueen，没有合进 v4-sim）**：`SHOWN_MOVE_BASES`（rollout-live，测出来的基础，整场模拟用 `EnemyMove.fightDamage` 加力量和易伤算；推演仍用显示值），`ALLY_STRENGTH_MOVES`（Burn Bright → 火炬头 +1），`AMALGAM_DEATH_STRENGTH`（女王 +2），You Are Mine 后火炬头已死就接 Off With Your Head。修后第 6 回合来袭 44.9 / 日志 49.9（修前 32.9）；逐招数值在 5HHLMV2DZ5AZ:16 上和日志一招不差（Beam 16×3、Tackle 3 27、Tackle 4 28、Off With Your Head 9×5）。

修准以后模拟更悲观了：同样的 Beam，日志的打法挡下大半（第 6 回合打穿 13.0），模拟只挡下一部分（30.4）。这是策略的问题（§13.6）。

### 13.4 无厌沙虫

**核对**（46 场）：Liquify Ground（第 1 回合，沙坑 4，塞 6 张狂乱逃离）→ Thrash 8×2 → Lunging Bite 28 → Salivate（+2 力量）→ Thrash 2 8×2 → Thrash …。沙坑：日志里 243 次相邻回合的变化，全部是「下回合 = 本回合 + 打出的狂乱逃离 − 1」，到 0 被吃（吞噬就是这个死法，不是一个出招）。死的 25 局里 6 局是血还够、被吃掉的。「成长」就是 Salivate 的力量，模拟里有。

**差在哪**：

1. **沙坑从来没进模拟**：沙坑是 Liquify Ground 给的能力，第 2 回合才出现；从第 1 回合或战前起点，模拟里既不会被吃，也不用花能量和出牌位打狂乱逃离（每打一张它的耗能 +1）。从第 5 回合起点（状态里已有沙坑）模拟是对的。

**修**：`EnemyMove.sandpit`（monster-db 的 SANDPIT_POWER 4），整场模拟里 Liquify Ground 给沙坑 4，之后 solver 已有的倒计时（+ 逃离 − 1、到 0 算死）接着算；`STATUS_INTO_DRAW`：Liquify Ground 的 6 张里 3 张洗进抽牌堆。修后敌人血量的下降速度接近日志（第 7 回合剩 96 对日志 124，修前更快），预测胜率 0.77 → 0.63（实际 0.47）。

### 13.5 知识恶魔

**核对**（52 场）：Curse of Knowledge（我们选一个诅咒：先 Mind Rot，再 Sloth 或 Disintegration，再 Waste Away）→ Slap 17 → Knowledge Overwhelming 8×3 → Ponder（11 伤害、+2 力量、回 30 血）→ Curse …。

**差在哪**：诅咒每场最多 3 次——日志 132 次 Curse 只出现在第 1、5、9 回合，之后 Ponder 接 Slap（第 13、16 回合）。出招模型里 Ponder → Curse 是 91%，长的模拟会给第 4、5 个诅咒。Ponder「只回两次」不对：第 12、15 回合的 Ponder 照样回血（RA3QYBLN7RJF），每次 30（到满为止），原来就这样建的。

**修**：`KNOWLEDGE_CURSES = 3`，用满后 Ponder 接 Slap；从战斗中途开始时，已用次数 = 我们身上已有的诅咒种数。只影响打到第 13 回合以后的样本，验证集上变化小（第 1 回合起 Brier 0.057 → 0.045）。

### 13.6 策略修正：试了，没有采用

（在分支的帝王蟹、女王修正之上做的。）

### 13.8 可信名单：标准和结果

标准（tools/boss-sim/trust.py 的常数，在看 B4 修后的数之前定的）：一个 boss 在某个起点上算可信，要同时满足：

1. 验证集（val_ext）至少 **10** 场；
2. 校准后 Brier 不高于该起点整体 Brier 的 **1.25 倍**；
3. 预测平均胜率和实际胜率相差不超过 **15 个百分点**；
4. 第 2–7 回合被打穿的血，模拟 / 日志在 **0.70–1.30** 之间。

B2（每条线的整场数字，`LOW_TRUST_BOSSES`）按第 1 回合起点的成绩判；B3（构筑题，`LOW_CONFIDENCE`）按战前起点判。trust.py 把每个 boss 的数、标准、两份名单和不满足哪一条写进 **src/sim/boss-trust.json**；src/sim/boss-trust.ts 读它，`LOW_TRUST_BOSSES` 和 `LOW_CONFIDENCE` 直接取它的两份名单（原因文字也从这里来；文件读不到时全部 boss 算低可信）。重跑验证后用 trust.py 重新生成即可，代码不用改。下表是 v4-sim 的数（整体 Brier：第 1 回合 0.124，战前 0.124；门槛 0.155）：

### 14.4 策略：一回合前瞻

**机制理由**。boss 的下一招在出招模型里大多是确定的（火箭 Charge Up 之后是 Laser，火炬头 Beam 的力量随 Burn Bright 上涨，瀑布巨兽固定 5 招循环），玩家和 5 回合推演都能提前一回合预见；实盘 solver 也拿到 combat-plan 算的 `nextIncoming`。整场模拟以前在第 2 回合以后把这个字段去掉了（起点那回合的已过时），策略只看本回合意图，常常为了伤害把血压到下回合挡不住的位置（例：FYQUP0GVWNUU:15 第 6 回合 25 血，模拟打完剩 1 血，下回合碾碎爪 21 + 火箭 6）。

**做法**（只在整场模拟里，`RolloutOptions.policyLookahead`，boss-sim.ts `BOSS_SIM_LOOKAHEAD`）：

- 每个策略回合，对每个活着的敌人按它这回合的意图、经过整场脚本（`fightNextMove`，在副本上）在 8 个等分点上抽下一招，取平均来袭（`nextAttacks`）：用的是出招模型的期望，不偷看这个样本自己的随机流；力量按这回合招式之后的算（Charge Up、Adapt），帝王蟹的钳子按朝向的平均（下回合朝向还不知道），敌人的虚弱交给 solver 看线打完后还剩没剩。
- 交给 solver 两样：`nextIncoming`（和实盘同一个字段，solver 已有的「安静回合不要自残到下回合打不住」、Plating 的吸收用它）；`nextHit`（新的可选字段，实盘不设）：这条线打完后，下回合还活着的敌人的来袭减去一手牌能挡的 12（`ERUPTION_NEXT_BLOCK`，瀑布巨兽爆炸规则里同样的数），本回合掉的血里落到这条线以下的部分多算 `lethal` 倍（`nextHitShortfall`）——和瀑布巨兽「爆炸线以下的血算双倍」是同一条规则推广到所有下一招。
- `threat`：HP 权重再乘 (1 + threat × 下回合来袭 / 当前血量)，下一招越重，现在的血越值钱。

**调参集上的选择**（每个配置 100 样本，b5-grid.md，tools/boss-sim/b5-grid.py）。事先定的规则：在前瞻的几个设置里，选四个目标 boss（帝王蟹、女王、无厌沙虫、瀑布巨兽）第 1 回合被打穿比最接近 1 的（Σ|ln 比| 最小），前提是折外校准 Brier（5 折按局拟合 Platt）三个起点之和不比不加前瞻差 0.01 以上；然后在验证集上看整体 Brier。

| 配置 | 原始 Brier 三起点和 | 折外校准 Brier 和 | 被打穿比 t1 整体 | 帝王蟹 / 女王 / 无厌沙虫 / 瀑布巨兽 | Σ\|ln 比\| |
|---|---|---|---|---|---|
| 无前瞻 | 0.3467 | 0.3282 | 1.141 | 1.139 / 1.519 / 1.142 / 1.207 | 0.869 |
| lethal 1 | 0.3519 | 0.3307 | 1.130 | 1.117 / 1.504 / 1.128 / 1.195 | 0.817 |
| threat 0.5 | 0.3535 | 0.3327 | 1.097 | 1.081 / 1.467 / 1.105 / 1.139 | 0.691 |
| threat 1 | 0.3583 | 0.3343 | 1.071 | 1.048 / 1.432 / 1.081 / 1.089 | 0.569 |
| **lethal 1 + threat 1（采用）** | 0.3628 | 0.3362 | 1.070 | 1.040 / 1.421 / 1.077 / 1.089 | 0.550 |
| 参照：B1.5 的本回合威胁项 1 | 0.3630 | 0.3361 | 1.048 | 1.042 / 1.429 / 1.050 / 1.056 | 0.501 |

和 B1.5、B4 一样，更防守的打法让被打穿的血对上了日志，调参集上的预测略差（折外校准和 +0.008，差在噪声量级）。B1.5 的本回合威胁项打法上最贴，但它是「照日志的样子挡」的行为项，没有新的机制理由，不在候选里，只作参照。

**验证集**（val_ext；两组修正都上时，加不加前瞻）：第 1 回合 0.1216 → 0.1215、第 5 回合 0.0914 → 0.0911、战前 0.1203 → 0.1207，预测不变（差都在 0.0005 以内，远小于 bootstrap 区间）；被打穿比 1.147 → 1.085，帝王蟹 1.35 → 1.27。事先定的「三个起点都不比不加前瞻差」在战前差了 0.0004，严格说没过；考虑到这在噪声以内、而前瞻是这次要修的「挡得少」本身，采用了，并在这里注明。耗时：同样的局面多 4%，战斗平均长 0.3 回合。默认开（`BOSS_SIM_LOOKAHEAD = { lethal: 1, threat: 1 }`），B2 和 B3 的整场模拟都用它。

### 14.10 遗留和要 Dai 定的事
