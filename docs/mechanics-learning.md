## 1. 统计什么（tools/build-monster-db.py → monster-db.json `observed`）

和数据库其余部分同一次读日志（每局结束后 ops/report.py refresh_knowledge 刷新），代码里**没有任何敌人或能力的名字**，所有能力、
逃跑招式、奖励都走同一套计数。只用**决策帧**：`observed` 帧可能是敌方回合中途拍的，却还标着我方回合（MCK9SMSK40ZY F19 T1：
结束回合之后格挡 28 → 11、顺走出现）。另外读 decisions.jsonl 里「结束回合」的决策（帧的 ts = 决策的 ts）：打死最后一个敌人的那张牌之后
没有帧，所以只有一回合最后一帧就是结束回合的决策时，才认为敌人活着进了敌方回合（没有这个文件时按最后一帧算，`end_turn_check: false`）。

每个怪物的 `observed`：
- **powers_stripped**（能力被去掉）：我方回合两个决策帧之间，敌人还活着，某个能力从有（数量 ≥ 0）变成没有、或从 > 0 降到 ≤ 0。
  `move_after` = 下一帧它的招式（STUNNED = 眩晕）、`stunned_share`；`co_removed` = 同一帧一起去掉的其他能力（拉加维林女族长的覆甲
  总是和沉睡一起去掉、仪式兽的力量和横冲直撞一起）；活到结束回合的里面：结束时还在眩晕的、去掉前显示攻击而结束时不再显示的
  （`attack_cancelled`）、它是唯一攻击者且攻击会穿过格挡时我们在敌方回合到底掉没掉血（`hp_check.landed` = 至少掉了应掉的一半）。
- **escape_moves**：回合开始时意图是逃跑（Escape）的招式：结束回合时活着的，下回合第一帧不在了（`gone`，含战斗结束）还是还在
  （`stayed`），各自有几次结束时在眩晕；我方回合里就被打死的（`killed_first` / `killed_last_card`）。
- **kill_rewards**：打赢的战斗的奖励屏（数字记成 N）。一个奖励在「它被击杀」的战斗里至少一半出现、在「它离场」的战斗里从不出现
  （`only_when_killed`），或在没有它的战斗里最多 2% 出现（`exclusive`）；出现总数 < 3 的不比较（随机遗物、药水）。
- **mid_turn_stuns**：我方回合中途招式变成 STUNNED，同一帧还发生了什么（某能力被去掉/降低、格挡被打光、有其他敌人死亡、掉血）。
  用来发现「去掉能力」以外的眩晕（噬尸蛞蝓：372 次全是有敌人死亡的那一帧）。

顶层 `observed.powers_stripped` = 每个能力在所有怪物上的合计（规则按能力定，不按怪物）。口径在 `observed.note` 和 `meta.note`。
**失败保护**：挖掘的任何一步出错，所有 `observed` 字段都不写（stderr 有一行说明），数据库其余部分照常；在完整日志上核对过，除了
`observed` 以外和改动前逐字节相同，耗时基本不变（约 50 秒）。`tools/monster-db-check.py` 的报告多了 (d) 节。

## 2. 规则：能力被打到 0 就眩晕（src/knowledge/mechanics.ts）

一个能力（顶层合计）是眩晕规则，当：去掉次数 n ≥ 5（再少就是个例）；≥ 80% 下一帧眩晕（日志里的比例是两极的：1.0 或 ≤ 0.44，0.8
在缺口里，也容得下偶尔一帧显示不准）；去掉前显示攻击的有 ≥ 3 次时，≥ 80% 在结束回合时不再显示攻击；能核对掉血的有 ≥ 3 次时，
攻击仍打出的 ≤ 20%。monster-db-check.py 的 (d) 节用同样的门槛（两处要一起改）。

**模拟器只对它能数层数的能力用这条规则**（turn-solver.ts `STRIP_COUNTERS`：振翅、滑溜、蜷身、人工制品；今天满足门槛的只有振翅）。
其余满足门槛的能力都已经有手写的眩晕（尖叫、横冲直撞 = `shriek`；埋地 = `burrowed`；沉睡、熟睡 = `asleep` / `slumber`），或者根本
不会被我们打掉（覆甲是跟着沉睡一起去掉的）。以后某个能力满足门槛、求解器又有它的计数器，不用改代码就会生效；没有计数器的，
学习者的机制审计会写「需要代码：给 X 加计数器」。

## 3. 模拟器和题面怎么用

- **求解器**（turn-solver.ts）：规划器给场上带着规则能力（数量 > 0）的敌人设 `EnemySim.stunOnStrip`（combat-plan.ts
  `applyStripStuns`）。一条线把它的最后一层打掉（开始时 > 0，线结束时 ≤ 0），敌方回合它的攻击不算进 hp_lost（`incomingHits`），
  `enemyHpAfter` 里标 `stunned` 和 `strippedStun {power, name, attack}`。
- **推演**（rollout.ts applyPlan）：求解器标了 `stunned` 的敌人走眩晕分支：本回合的招不发生（不加力量、格挡，不花活力），逃跑取消、
  下回合再逃（招式表的 Escape → Escape），下一招照招式表。小偷第一步手写的「振翅被打光就取消逃跑」检查（`fluttered`）只在规则数据
  不覆盖这个敌人时还用（没有数据时和第一步完全一样）。推演的后续回合也由求解器算，所以后续回合打光振翅同样取消攻击。
- **题面**：每个选项多一条 `stripped_stun`：「stuns 偷窃草蜢 (its last 振翅 stripped): its attack this turn (21) is cancelled, already
  left out of hp_lost」（逃跑回合：「its move this turn is cancelled」）；敌人的振翅后面加「observed in the logs, not in its text: …
  41 of 41 strips in 41 fights; the options' numbers already count it」（只加在求解器真的用了规则的能力上）；小偷事实里原来的「hp_lost
  above still counts its attack」变成「hp_lost above leaves its attack out」。决策日志多一个 `mech`：场上的规则、能触发它的选项、所选的线
  是否触发。
- **知识前缀**（DeepSeek）：怪物块多一个「观察到的机制（日志统计，能力描述里没写；n 为次数）」小节，每个值得说的观察一句短话（满足规则
  门槛的能力、逃跑招式、击杀才有的奖励、去掉能力解释不了的回合中眩晕）。A8 前缀 182,349 → 183,461 字（+1,112，+0.6%，约 780 个
  DeepSeek token），只有十来个怪物有这一节。例：「振翅：观察到在我方回合被打到 0 层（去掉）时它立即眩晕、本回合行动取消（41 场 41/41
  次；当回合有攻击的 10/10 次攻击取消）」。

## 4. 开关和失败保护

`MECH_RULES`（src/config.ts，默认 on，.env.example 有说明；写错只给警告、按 on；run-config 记 `loop.mech_rules`）：
- off：战斗题面、选项、每个答案的处理和 v4 ffed0d4 逐字节相同，知识前缀和以前相同。tests/mech-rules-planner.test.ts 钉住 6 个日志
  局面 × JEV_CONTEXT off/v1 的摘要（在 ffed0d4 上算的，数据库里**带着** observed 数据）；
- on 但数据库没有 `observed`（规则刷新前的旧数据库）：同 off（同一组摘要）；
- 读规则出错：同 off（同一组摘要）；规划时出错：关掉规则再规划一次（`withMechFallback`；别的原因的错误照旧抛出）。

## 5. 机制审计（离线，只出提案）

**残差工具** `npx tsx tools/mechanics-residuals.ts run [--shards 8] [--monster-db <带 observed 的库>]`（8 个进程约 3 分钟）：每个记录的
战斗回合，取第一个规划决策的状态，用现在的代码规划两次（规则关/开，只取求解器的线），在线里找出当时实际打出的线（卡 id + 目标；
第一个决策之后打了抽到的牌就用之后重新规划的那个决策），它预测的本回合掉血对比实际掉血；按场上的敌人能力、本回合被去掉的能力、
敌人分组，按偏差和 |误差| 排序，附能力描述和 `observed` 统计。输出 notes/mechanics-residuals.md 和 experiments/mechanics/summary.json
（逐回合的 rows-*.jsonl 不提交）。2026-10-02：28,512 个回合，能对上的 27,716。
