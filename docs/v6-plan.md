## 1. 目标与原则

**目标**

1. 构筑以打过第三幕 Boss 和最终连战（F48→F49）为目标，并有量化依据。
2. 拿牌、选药由 Jev 按代码算好的条目快速决定；大脑只给方向条目和处理例外。
3. 学习者的经验沉淀为 Jev 能直接使用的通用量化条目（“小脑记忆”），并以全局构筑为核心组织。
4. 出牌架构不变，持续完善给 Jev 的条目。

**原则**

1. **代码量化，Jev 选择，大脑给方向和例外。** Jev 只读条目，不做计算；条目必须是数值（带误差和样本数）或固定词表的枚举，不给 Jev 大段零散文字。
2. **游戏知识只来自学习者。** 核心构筑卡、理想补齐清单、小脑记忆条目、药水与牌的分类，都由学习者从本角色对局证据得出并带局号（[学习协议](learning-protocol.md)）。watcher 和开发会话只做格式、计算、加载、校验和接入。
3. **不做“Jev 和代码谁更强”的对照实验。** 只做功能健康检查（耗时、覆盖、未知、故障），上线后按 G1c 固定分段漏斗和第 10 节指标监控。
4. **模型不可信时照常给数，但必须带标签。** 第三幕和连战的投影带可信度及已知偏差方向；以同种子配对差为主，绝对值为辅。H0 继续并行。
5. **只给方向概率，不定主备。** 核心构筑方向只有几个，大脑每次输出全部方向的概率；剩下交给 Jev。
6. **角色通用。** 所有模块按角色读取各自的知识文件；没有知识文件的角色保持原行为。铁甲、Regent 在开关关闭时逐字节等价。

## 3. 全局构筑

### 3.1 大脑：构筑方向概率

大脑在幕初与触发重规划时输出（JSON，由代码校验）：

| 字段 | 内容 | 校验 |
|---|---|---|
| `direction_weights` | 方向 ID → 概率，覆盖本角色方向目录中的全部方向，和为 1（±0.01） | ID 必须在目录中；不允许缺项 |
| `ideal_overrides` | 可选：某方向的理想补齐优先级覆盖（牌 ID 列表） | 只能引用该核心构筑卡中出现过的组件或本局已出现的牌 |
| `potion_directions` | 药水方向条目（第 4 节） | 档位为固定枚举 |
| `route` / `rest` / `checkpoint` | 沿用现有整局计划字段 | 沿用现有校验 |
| `reason` | 简短理由 | 长度限制 |

- 方向目录取自学习者核心构筑卡（第 6 节），Silent 当前为 P、D、S、R。没有核心构筑卡的角色不启用 V6 构筑。
- 题面给大脑：第 3.2 节的幕初方向评估表（全部方向 × 全部目标，档位、配对差、可信度标签）、各方向补齐可得率、核心构筑卡摘要、当前牌组/遗物/血量/地图。
- 大脑不再逐题回答拿牌。

### 3.2 投影模拟：按组合计算“凑齐概率 × 胜率”

Roy 2026-10-19：拿牌条目必须以牌组为单位，按“当前牌组 × 未来可拿理想牌的概率 × 对 Boss 胜率”判断；把所有构筑方向 × Boss 胜率告诉 Jev，由 Jev 选牌；不用单牌过关率量化。

对每个选项 o（拿某张牌，或跳过）、每个组合 k（第 6 节，由学习者定义）、每个目标 Boss b：

| 量 | 含义 | 计算 |
|---|---|---|
| P_k,b(o) 凑齐概率 | 选 o 后，在打 b 之前凑齐组合 k（含组合要求的升级）的概率 | 供给蒙特卡洛：按本角色本进阶的历史供给（`construction-opportunities.json`，按幕、层段、来源）模拟后续奖励与商店出现的牌；每次奖励最多拿 1 张，商店受当前金币与历史金币增长限制，升级受历史休息点次数限制；统计凑齐比例。默认 200 次供给模拟 |
| W_k,b(o) 凑齐后胜率 | 牌组 = 当前牌组 + o + k 中仍缺的牌（按组合升级要求）打 b 的胜率 | 同种子配对模拟；拿牌时每格 20 场，幕初 100 场 |
| W_0,b(o) 凑不齐胜率 | 没凑齐组合时，按历史一般补牌（从本角色本进阶历史局在相同层段的实际加牌、升级、删牌中抽样）后打 b 的胜率 | 同上；多份补牌样本分摊场次，条目标明来源 `empirical` |
| E_k,b(o) 组合期望 | P_k,b · W_k,b + (1 − P_k,b) · W_0,b | — |
| V_d,b(o) 方向值 | 方向 d 下各组合期望的最大值 | — |
| V_b(o) 加权值 | Σ_d p_d · V_d,b(o)，p_d 为大脑给的方向概率 | — |

| 项 | 规则 | 数据来源 |
|---|---|---|
| 目标集合 | 本幕 Boss（作为门槛单列）；后续幕候选 Boss；第三幕三个 Boss；F48→F49 连战（接力模拟，不用单战胜率相乘）。连战期望即“通关估计” | 本角色实际遇到频率作权重；`double-boss.json` |
| 进场血量 | 本幕 Boss：现有路线投影；更远的 Boss：本角色本进阶该层历史进场血量比例中位数 × 最大血量；F49：接 F48 剩余血量（复用 G1a `continuous-boss-result`） | 路线投影；日志统计 |
| 遗物、药水 | 当前持有；未来不预测，在限制中写明 | — |
| 组合来源 | 学习者 `build-cores.json` 的组合（第 6 节）；大脑 `ideal_overrides` 作为该方向的临时组合（来源标 `brain`）；学习者产出前，用 `construction-templates.json` 的要求签名作为各方向的过渡最小组合 | 知识文件；大脑答案 |
| 计算量控制 | 同一组合内的牌共享凑齐后牌组，结果缓存；P_k < 5% 的组合不模拟，只报凑齐概率；每个方向最多评估 4 个组合（按幕初评估的期望排序）；拿牌时只算概率 ≥ `V6_DIRECTION_MIN_WEIGHT`（默认 0.10）的方向；幕初算全部方向与组合 | 配置 |

**这个公式的性质**：o 属于组合 k 时，凑齐后的牌组与跳过时相同，o 的价值只体现为 ΔP_k ×（W_k − W_0）；o 不属于 k 时，凑齐后的牌组多出 o，价值体现为 W 的变化（稀释或加强）。每张牌都放在“当前牌组 + 未来可拿的牌 + 要打的 Boss”里评价。

复用：`BossSimPool` / B3 池、`human-pace-direction.ts` 的变体与预算切分、`continuous-boss-result.ts`、`double-boss-start.ts`、`route-projection.ts`。V5 的“当前牌组 + 核心组件”变体由本节取代；H2 的“S 不参与排序”“第二幕临时目标”规则在 V6 打开时不再适用。

### 3.3 给 Jev 的拿牌条目

单牌过关率等单牌统计不发给 Jev。20 场下胜率误差约 ±11 个百分点，所以同时给档位、配对差和波动更小的连续指标。

| 类型 | 条目 | 形式 |
|---|---|---|
| 数值 | 每个组合 × 目标：凑齐概率（拿 / 跳过）、凑齐后胜率、凑不齐胜率、组合期望及与跳过的配对差 ± 标准误 | 百分比 |
| 数值 | 每个方向 × 目标：方向值（最佳组合）；按大脑方向概率加权的值 | 百分比 |
| 数值 | 连战 F48→F49 期望（通关估计）及与跳过的配对差；本幕 Boss 门槛 | 百分比 |
| 数值 | 组合摘要：每回合伤害、启动回合、历史胜率与样本数（第 6 节） | 数值 |
| 数值 | 输局 Boss 剩血比例；赢局我方剩血比例；打完回合数 | 比例、回合 |
| 数值 | 牌组张数变化；核心牌平均首次打出回合（来自同题模拟） | 张、回合 |
| 枚举 | 胜负档：`certain_win` ≥95% / `favored` ≥70% / `even` >30% / `unfavored` >5% / `certain_loss` ≤5%（n=20 时分别为 19–20 / 14–18 / 7–13 / 2–6 / 0–1 胜） | 五档 |
| 枚举 | 与跳过比：`much_better` / `better` / `same` / `worse` / `much_worse`（>2 个配对标准误且 ≥5 个百分点为 much；>1 个标准误为 better/worse） | 五档 |
| 枚举 | 这张牌在各组合中的角色：`in_combo`（附作用）/ `off_combo` / `conflict` | 来自构筑卡牌池 |
| 枚举 | 模型可信度：`trusted` / `low_optimistic` / `low_pessimistic` / `unknown` | 来自本角色 `boss-trust.json` 的门槛结果与偏差符号 |

阈值全部为配置项，以上为初值。题面为英文短题面（沿用 H2 已批准的 Jev 例外），只放事实，不放实际大脑选择或大段经验原文；未知保持 `unknown`，不补 0。示意：

```text
Direction weights (brain): P 0.50  D 0.30  S 0.15  R 0.05
card1 BOUNCING_FLASK   [P: in P-common, P-dpr | D: off | S: off]
  P-common  reach 58%→74% (+16)  if reached: act boss 81%, F48 55%, F48→F49 24%
            E[F48→F49] 15%→19% (+4 ±2)
  P-dpr     reach 21%→30% (+9)   if reached: F48→F49 33%   E 10%→12% (+2 ±2)
  D-common  reach 35% (=)        F48→F49 19%→18% (−1 ±2, dilution)
  weighted E[F48→F49] 14.1% → 16.2% (+2.1 ±1.2); act boss 80% → 80%
skip: weighted E[F48→F49] 14.1%
```

（数字仅示意格式。）

### 3.4 Jev 拿牌题

- 题型：`choice`，选项为每张候选牌及 `skip`；题面共享部分放方向概率、各方向补齐可得率与可信度说明；每个选项放第 3.3 节条目。
- 执行：Jev 的选择经现有执行闸执行；记录选择、概率、置信度、耗时、用量。
- 兜底（Jev 报错、超时或无效答案）：按代码规则执行——先排除本幕 Boss 档位为 `much_worse` 的选项，再取加权连战配对差最大者，并列取加权本幕 Boss 配对差最大者，仍并列取 `skip`。兜底记 `fallback`，连续两次计入触发条件 T6。
- 商店买牌、删牌、升级在 W7 按同样模式迁移；迁移前保持现有大脑路径。

### 3.5 大脑何时介入

默认只在每幕开始介入。下列情况由代码检测，触发大脑重给方向条目（同一回合多个触发合并为一次调用）：

| 编号 | 触发条件（默认阈值，可配置） |
|---|---|
| T1 | 概率最高方向的“核心补齐概率”低于 0.30 |
| T2 | 某方向的连战投影比概率最高方向高出 max(2 个配对标准误, 5 个百分点)，连续 2 次评估 |
| T3 | 候选牌是概率 < 0.20 的方向的核心件，且拿后该方向的连战投影超过概率最高方向（同 T2 门槛） |
| T4 | 获得的遗物或事件结果出现在某核心构筑卡的要求或转向信号中 |
| T5 | 本幕 Boss 投影进场血量低于现有路线投影的危险线 |
| T6 | 本题未知条目占比 > 50%，或 Jev 连续 2 次兜底 |
| T7 | 到达大脑上次给出的复查层 |

每局大脑调用软上限 15 次；达到上限后只保留 T5、T7 和幕初。所有触发、合并与跳过都写日志。

### 3.6 预算、缓存与降级

- 缓存键：牌组哈希、遗物哈希、方向、补齐清单哈希、目标、种子集、模型版本。“跳过”基准按方向缓存，牌组不变时复用；幕初评估结果在本幕内复用。
- 预计算：幕切换、路线移动、动画与过场期间，提前算下一题可能用到的“跳过”基准。
- 拿牌、选药、商店、休息等构筑类选择：计算预算 5 秒，Jev 最多 5 秒（Roy 2026-10-19：Nova 实测单次约 1.5 秒，“jev 放开到5s都行”）；战斗回合的 Jev 预留不变。计算超时按顺序降级：去掉概率最低的方向 → 只保留本幕 Boss 与连战目标 → 剩余项标 `unknown`。降级写日志，不延长等待。
- 机器 32 核；W3 实测各角色、各幕的单场耗时后定 worker 数，对局运行时后台任务仍守 ≤4 进程与 `nice` 规则，对局内 worker 池沿用现有上限。

## 5. 小脑记忆（reflex 经验）

拿牌、商店、休息、药水等构筑类选择的条目按第 3.2 节以牌组为单位计算，单牌统计不发给 Jev；小脑记忆条目用于出牌等需要按条件判断的场景，内容也按核心构筑关联（`cores`、`combos`）。

### 5.1 条目格式 `reflex-entry-v1`

| 字段 | 内容 |
|---|---|
| `id`、`version` | 唯一 ID，版本 |

## 6. 以全局构筑为核心的经验体系：核心构筑卡

Roy 2026-10-19：核心构筑方向下可以有很多组合，不按牌数分，凡是符合的都可以收入，但组合里的每张牌都必须对这个方向有用；例如必拿最小组合、常用组合、最多牌组合、每回合伤害最高组合等，有的牌会跨组合；先建立组合，再把相关经验关联上去；组合信息要尽量多，包括每回合伤害能力估算、启动回合、历史胜率等。

新文件 `knowledge/characters/<角色>/build-cores.json`，格式 `build-core-v1`（取代原计划的 `direction-card-v1`），每个方向一张，由学习者维护：

```json
{
  "direction": "P",
  "name": "<学习者命名>",
  "status": "candidate | validated",
  "card_pool": {
    "<CARD_ID>": {"roles": ["core | starter | output | defense | draw | support ..."],
                  "contribution": "<它对本方向的作用>", "upgraded_matters": true,
                  "combos": ["P-common"], "evidence": ["<局号/层/回合>"]}
  },
  "combos": [
    {"id": "P-min", "types": ["must_pick_minimal"], "boss": null,
     "cards": [{"id": "<CARD_ID>", "count": 1, "upgraded": false}, {"any_of": ["..."], "count": 1}],
     "metrics": {}, "fits": {}, "evidence": {}, "confidence": "low | med | high"}
  ],
  "pivot_signals": ["..."], "failure_modes": ["..."],
  "linked_experience": ["..."], "linked_reflex": ["..."]
}
```

**规则**

- 组合数量不限，不按张数分；`types` 可多选：`must_pick_minimal`（必拿最小组合）、`common`（常用组合）、`max_cards`（最多牌组合）、`max_dpr`（每回合伤害最高组合），以及 `boss_specific`、`defensive` 等，学习者可按证据新增类型。
- 组合里的每张牌都必须在本方向 `card_pool` 中，写明作用和证据；说不清作用的牌不能进组合。同一张牌可以属于多个组合。
- 每个组合的 `metrics`（实战与模拟分列，每项附样本数和口径；样本少时标出）；统计口径见下方“统计不分版本、不分进阶”）：

| 类别 | 指标 |
|---|---|
| 伤害能力 | 成型后每回合伤害（Boss / 精英 / 普通战分开；中位与 p25/p75）；伤害随回合增长（第 1–3、4–6、7 回合以后各段每回合伤害）；单回合最高伤害；多敌时的群体伤害 |
| 防御能力 | 每回合格挡；每回合实际掉血 |
| 启动 | 启动回合（组合核心首次全部生效的回合，中位与分布）；启动所需能量与抽牌；首次凑齐的层（中位） |
| 历史战绩 | 凑齐过的局数；通关局数（首试与含 SL 分开）；平均到达层；对每个 Boss 的到达、胜、胜率；F48→F49 连战 |
| 可得性 | 组合内每张牌按幕的历史出现率；历史凑齐率 |
| 牌组规模 | 成型时牌组张数范围；牌组变大后的表现变化（观察） |
| 资源依赖 | 药水、SL、关键遗物 |
| 模拟（代码计算） | 标准进场血量下对各 Boss 的模拟胜率与每回合伤害；可信度标签 |

- **统计不分版本、不分进阶**（Roy 2026-10-19：“数据不要按照代码版本来分，合在一起”；进阶是在前一级某一点上的静态提升，可以统一处理）：
  - 代码版本只作为来源字段保留，全部合并统计；需要时按时间加权（新局权重大），不切分。
  - 我方能力类指标（每回合伤害、格挡、启动回合、首次凑齐层、牌组张数、凑齐率、可得率）不受进阶影响，所有局直接合并。
  - 与敌人强度有关的指标（Boss 胜率、掉血、打完回合数）统一折算到当前目标进阶（Silent 为 A10），两种口径并列：(a) 模拟折算：把历史局中该组合的实际牌组放到 A10 静态数据下模拟；(b) 实战折算：所有进阶的实际胜负合并做回归，进阶只作一个统一偏移项，输出折算到 A10 的胜率与误差。
  - 样本少的组合向所属方向的整体值收缩（分层收缩），避免 1–2 局的极端值；原始计数照常列出。
  - 每级进阶改了什么作为一张静态表，由学习者从对局观察维护，供折算与解释使用，不在每张卡上重复切分。供给与可得率同样合并所有版本和进阶，学习者发现某级进阶影响供给时再作为统一偏移。
- `fits`：适合与不适合的 Boss、路线（精英多少、休息与升级需求）、情况（血量、遗物、牌组规模）。
- 经验按组合重新归纳：`experience.json` 条目追加 `cores`、`combos` 关联字段（不删原条目、不改原证据）；组合也列出关联经验。
- 构筑卡是第 3.2 节组合来源、第 3.3 节组合摘要与角色枚举、第 3.5 节 T3/T4 的数据来源，也供大脑幕初阅读。实战指标由学习者先在任务中计算（保存命令与口径），之后由 `knowledge/builders/` 的生成器按同一口径定期刷新（W2.2）。
