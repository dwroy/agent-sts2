# MECH_MOVE_RULES：第二类学到的机制（换招）和凯撒蟹（2026-10-02）

分支 v4-mech2（从 v4 3488dc5）。Dai 2026-10-02 定：做第二个数据规则类「能力被去掉 → 敌人换招」，并查凯撒蟹。口径和实现见
docs/mechanics-learning.md §8；逐回合的数在 notes/mechanics-residuals.md（残差）和 notes/mech-move-replay.md（回放）。不调用任何模型。

## 结论

1. **B 类规则**（能力在我方回合被去掉或少一层 → 那一帧招式就变了）。挖掘对所有怪物、所有能力一视同仁；6,112 场里 n ≥ 5 的组合，换招比例要么
   0%，要么 87.5–100%，而且都只换成一个招，门槛（≥ 80% 换招、≥ 80% 换成同一个招，不算眩晕）落在缺口里。满足门槛的：
   - 巨斧机器人 × 库存：去掉（1 → 0）22/23、少一层（2 → 1）22/22 → **启动 BOOT_UP**（无攻击），下回合上勾锤击 21/22；**求解器和推演用**。
   - 巨斧机器人 × 力量 25/26、易伤 27/28、虚弱 7/8 → 启动：同一帧复活带走的，求解器看不见它们被去掉，不单独用；作为「随库存换招一起去掉的能力」
     在推演里清掉。
   - 瀑布巨兽 × 易伤 38/38、力量 10/10 → 即将爆炸：被打到 0 变空壳带走的，求解器看不见；变空壳本来就手写了。
   - 不换招的：蟹之怒（27 次，0 换招）、滑溜、蜷身、人工制品等全部 0；眩晕（振翅、埋地、尖叫……）是 A 类。
2. **凯撒蟹**：B 类不适用（蟹之怒去掉时另一只的招式从不变）。
   - 「−2.3/回合」大部分是**残差工具**的问题：它不知道实盘记着的朝向（Surrounded），每回合按开场的朝向算；补上以后 537 个回合 −0.4。
   - 真正的机制错误：**背后攻击要两只钳子都活着**。一只死的那一刻，另一只的 ×1.5 就没了（27 次死亡里，当时在背后出招的 10 次全部这样，例 TQX5JJX3UD39 F33 T4
     激光 49 → 39 = 31 + 8 力量）；之后只剩一只，152 个攻击意图全部没有 ×1.5。求解器原来在死的回合留着 ×1.5（多算约 1/3），只剩一只时用记住的
     朝向把一个本来没有的 ×1.5「去掉」（少算 1/3，8L29N792FA45 F33 T5 预测 5 实际 11）。按 C 类手写修了（`PlayerSim.backAttackPair`），也在
     MECH_MOVE_RULES 后面。蟹之怒的 +99 格挡和 +6 力量（文字写 5）本来就对；死掉的钳子不再攻击，两边一致。
3. **残差**：凯撒蟹一只钳子死的回合 −7.1 → −6.2（剩下的是随机目标的飞剑回旋镖、没建模的遗物迷失鬼火（打能力牌对所有敌人 8 点）、求解器的线没打死而游戏打死了：不是蟹的
   机制），只剩一只钳子 +0.3 → 0.0（|误差| 0.37 → 0.09）；预测变了的 11 个回合 |误差| 3.4 → 0.4（10 个变得和实际一样）；巨斧机器人不变（−0.1）。其他所有分组没有变差。
4. **回放**：凯撒蟹 560 个回合里代码自打的线变了 5 个、问 Jev → 代码自打 1 个、问 Jev 的选项 hp_lost 变了 26 个、rollout_best 变了 23 个；巨斧
   机器人 135 个回合里选项的 hp_lost 一个没变、40 个回合的选项有换招事实、rollout_best 变了 60/122（推演后面的回合复活后走启动、清掉力量和
   易伤；一部分是 8 样本的抽样噪声）。开的模型自己认为更差的：0。
5. **整场 boss 模拟**：同一个错误也在里面（见下），修正通过同一个开关进去；23 场验证集上第 1 回合校准胜率 0.444 → 0.451（实际 0.391）、Brier 0.1466 → 0.1493、被打穿 1.266 → 1.261 倍；可信标准仍满足，但 Brier 贴着门槛（0.1496），建议合并时重跑可信校准（这里没改 boss-trust.json）。

## 开关和测试

- B 类要用新 build-monster-db.py 建出来的数据库（`observed` 里有 move_changed 等字段）：合并后运行工作树每局之后刷新数据库时就有了；在那之前
  旧数据库里没有这些字段，换招规则是空的（等于关），凯撒蟹的修正（C 类，不靠数据）照样生效。

- `MECH_MOVE_RULES`（默认 on，要 MECH_RULES 也开）。off 或 MECH_RULES off：战斗题面、选项、每个答案的处理和 v4 3488dc5 逐字节相同
  （tests/mech-move-planner.test.ts：4 个日志局面 × JEV_CONTEXT off/v1，摘要在 3488dc5 上算的）；知识前缀和只开 MECH_RULES 时相同。
- 失败保护：读规则出错 → 关掉 MECH_MOVE_RULES 重新规划（凯撒蟹的修正一起关），再错再关 MECH_RULES（测试钉住出错时和 off 一样）。
- B3、小偷卡价值的合成 boss 起点读 process.env 的开关；boss 回测（tools/boss-sim/backtest-board.ts）也读，`MECH_MOVE_RULES=off` 就是改动前的回测。
- tests/mech-move-rules.test.ts：规则门槛、求解器（启动、有攻击的新招、库存 2 → 少一层、凯撒蟹三种情况）、推演（复活后启动 → 上勾锤击、力量清掉）、
  applyMoveRules、知识前缀、开关。

## 整场 boss 模拟（B2/B3）

**同一个错误也在整场模拟里。** 整场模拟（rollout.ts 的 whole fight）后面的回合里，没面对的那只钳子按 ×1.5 算（`behind`），不管还剩几只：
样本里一只钳子死了以后，朝向停在死掉那只的序号上，活着的那只每回合都按背后 ×1.5 打，直到策略的线对它出牌；死的那个回合求解器也留着它的 ×1.5。
修正走同一个开关进去：B2 用规划器的输入（`backAttackPair` 在 PlayerSim 里），B3 和小偷卡价值的合成起点读 process.env 的开关，回测
（tools/boss-sim/backtest-board.ts）也读，`MECH_MOVE_RULES=off` 就是改动前的回测。

在 val_ext 的 23 场帝王蟹上量了（tools/boss-sim/backtest.ts `--enc CRUSHER --set val_ext --starts t1,pre --samples 200 --no-rollout`，fights-1002，
同一份代码开关关 / 开；校准用 boss-trust.json 现有的 Platt 映射；关的结果和 b5-final 的帝王蟹行一致：0.445 / 0.147 / 1.266）：

| 起点 | 原始胜率 关 → 开 | 校准胜率 关 → 开（实际 0.391） | 校准 Brier 关 → 开 | 被打穿 模拟/日志 关 → 开 |
|---|---|---|---|---|
| 第 1 回合（B2） | 0.372 → 0.380 | 0.444 → 0.451 | 0.1466 → 0.1493 | 1.266 → 1.261 |
| 战前（B3） | 0.351 → 0.360 | 0.439 → 0.447 | 0.1388 → 0.1404 | 1.240 → 1.234 |

影响很小：只剩一只钳子的阶段在样本里不长，策略多半很快对它出牌；被打穿多出来的 1.27 倍主要是别处来的（模拟的策略比实际挡得少，boss-sim.md §13.6）。
可信标准仍然都满足，但第 1 回合的 Brier 0.1493 贴着门槛（整体 0.1197 × 1.25 = 0.1496）；这些差别在 200 样本的噪声以内。**建议合并时重跑帝王蟹的
B5 回测行和 tools/boss-sim/trust.py**（帝王蟹可能落到低可信，那样 B2 就不再按整场数字给它排序）。boss-trust.json 这里没有改。
