|---|---|---|---|
| bottled_ai (xaved88) | github.com/xaved88/bottled_ai | Combat: enumerates every play order with a simulator, then scores each end state with a weighted evaluation of about 40 factors. Everything else uses hand-written priority lists per strategy and conditional event rules. No machine learning. | Best is Watcher at 52% win rate. **Lessons for our split (code = turn solver + rules, Jev = fast chooser, DeepSeek = slow LLM)**

1. **Combat is a search problem, and every strong bot uses search.** bottled_ai uses enumeration plus an evaluation; lightspeed and destire-mio use MCTS. Six attempts to replace search with networks all failed, because combat depends on future draws, which only rollouts see. LLMs lose to search on exact moves (FDG 2024). Our turn solver should stay the owner of combat. Jev should only break ties among lines the solver has already scored as close, which matches its measured edge (2.59 vs DeepSeek 3.12 extra HP lost). DeepSeek should stay out of card sequencing, consistent with its trade-HP-for-damage flaw.
2. **Deck building, pathing and shops are judgement calls, and learned or LLM layers help there.** destire-mio's biggest gain (+11 floors, 2%→14% wins) came from a learned non-combat scorer, not from better combat. Its authors say judgement decisions "compress easily" while planning decisions resist. This supports DeepSeek owning build direction.
3. **Top bots avoid rigid playbooks with an evaluation function plus search, not with more if-then rules.** bottled_ai's combat has no playbook, only about 40 weighted terms applied to simulated end states. Its non-combat side is exactly the rigid priority lists the user worries about, and it needs one list per character strategy. Best practice: encode what we learn as evaluation terms (value of block now vs HP later, scaling, exhaust synergy) and let search combine them. Avoid "in situation X do Y".
4. **Value a card by what it does to this deck against the coming fights, not by a fixed tier list.** Slay-I scores a card as HP saved in expected fights. We already have a simulator, so a cheap version is to simulate the upcoming elites or boss with and without the candidate card. That gives DeepSeek or code a grounded number and cuts DeepSeek's variance.
5. **Can Jev get our lessons through its prompt? Yes, if they are small and triggered.** The upstream design caps cross-decision memory at a code-curated Run Brief of about 150–300 tokens, and Jev loses accuracy when unrelated text is added. AgenticSTS's biggest win came from triggered skills: short guides retrieved only when their situation fires. They did better than a large static handbook, and full transcripts did badly (0/5 wins). So Jev should get 1–3 relevant lesson lines selected by code per screen and enemy (e.g. "vs this boss: keep block ≥ X on turn N"), never the whole handbook. DeepSeek can take a larger triggered set.
6. **Route decisions by tier, which we already do.** AgenticSTS's split (fast / strategic / analysis / evolution) matches code / Jev / DeepSeek / post-mortem subagent. Its data supports DeepSeek for direction and mid-run pivots, and escalating by stakes rather than calling it per action.
7. **Keep post-run memory writable, but gate what gets written.** Runs with post-run memory reach A6–A8 vs A2–A4 without. They pass lessons through a write gate, and hand-authored and auto-authored skills performed the same. This suggests the post-mortem loop should mostly write triggered skills or evaluation terms, and turn only deterministic bug fixes and safety rules into code.
8. **Do not assume skills written for one model transfer to another.** AgenticSTS saw DeepSeek V4-Pro drop 18% with skills tuned for Gemini while Qwen gained 84%. Our guide and handbook for DeepSeek should be A/B tested on DeepSeek itself. That fits our finding that guide edits did not fix its HP trading and the code HP guard did (uncertain whether it applies to deepseek-flash).
9. **Ascension scaling is the weak point for everyone.** destire-mio falls from floor 38.5 to 25.7 between A0 and A20, and no bot on record wins at A20. At A2+ the leverage is mainly deck quality and elite and boss preparation (see lesson 2), not combat polish.
10. **Mapped to the user's proposed split:** combat stays with the solver's evaluation plus search (we already have that code). Jev picks among close lines, gets per-situation lesson lines, and should not be given a playbook. DeepSeek sets the build direction and pivots, using simulated card value and triggered skills. Code keeps legality, safety guards, mechanics, and bug-level lessons only.
