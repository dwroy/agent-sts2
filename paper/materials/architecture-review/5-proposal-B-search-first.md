# 下一版架构提案：先做搜索和评估（search/eval-first）

**核心判断**：开源项目里所有能打的 STS bot，战斗都交给"模拟加评估"。bottled_ai 枚举全部出牌顺序，再对结束状态按约 40 项加权打分；lightspeed 和 destire-mio 用 MCTS。destire-mio 列了 6 次用网络取代搜索的尝试，全部失败。死套路的解法是"评估函数 + 搜索"，不是更多 if-then。所以本方案的分工是：
- 代码负责事实和模拟：机制、模拟器、安全护栏。
- 模型负责判断，但只输出两样东西：评估权重，和 intent（战略意图，比如流派和风险姿态）。模型不直接挑具体动作。
- 用户提的三层分工（DeepSeek 管构筑和方向，Jev 管出牌，代码管死操作）基本成立，本方案只做一处修正：DeepSeek 构筑时要看模拟器算出的数，不凭感觉挑牌。

## 1. 按决策类型分工
| 决策 | 负责方 | 做法 |
|---|---|---|
| 战斗出牌 | 求解器 + Jev | 求解器枚举出牌顺序并打分，差距 ≥6 时代码直接出（目前 2,778 次，占 100%）。接近时交给 Jev 从前几名里选：Jev 实测多掉 2.59 HP，DeepSeek 3.12，代码排第一的线 3.67。DeepSeek 退出出牌，因为它拿 HP 换伤害的毛病改提示词改不掉。 |
| 药水时机 | 代码模拟 | 现在 plan-choice+potion 有 64% 交给 DeepSeek，这是它出错最多的地方。改为对"喝 / 不喝"各跑几次剩余战斗的 rollout，比较预期 HP 损失。比较接近时交给 Jev。固定的药水成本常数 4/5/15 和 0.6 删掉。 |
| 卡牌奖励 | 代码算 Δ，DeepSeek 在接近时做判断 | 参考 Slay-I：把"加入这张牌后，打接下来的精英 / Boss 少掉多少 HP"算成 ΔHP，作为主要特征。约 110 张牌的 tier 表降为先验。差距小，或处在关键节点时，交给 DeepSeek，并把 ΔHP 写进它的 state。 |
| 商店 | 代码算 Δ，DeepSeek 每店一次 | 每家店只调一次 DeepSeek，出一份购物方案（买哪些、删哪张），代码再校验金币和合法性。`value-62-cost/25` 这类公式降为兜底。 |
| 事件 | DeepSeek，代码过滤 | 维持现状（DeepSeek 占 77%），加上事件 HP 护栏。 |
| 升级 / 删牌 | 代码 | 升级按 Δ 模拟排序；删牌顺序（诅咒 > Strike > Defend）本来就是确定性的，保留。 |
| 地图 / 休息 | 代码 | 用"按当前牌组模拟出的每类战斗 HP 成本"给路线打分。风险姿态（本幕打几个精英）由 DeepSeek 在检查点给出。休息阈值改为"预计打 Boss 会掉的 HP"，替换固定的 0.85。 |
| Boss 专属战术 | 代码 + 提示 | 机制事实（Sandpit、Crab Rage 等）进求解器。战术经验做成带触发键的 `fight_hints` 给 Jev。7 个 Boss 的卡牌加分全部删掉，改用对该 Boss 的 Δ 模拟。 |
| 方向 / 转型 | DeepSeek | 只在检查点调用：F3 前后、每个精英或 Boss 遗物之后、每幕开始。输出结构化 intent：流派、缺什么（前期伤害 / 防御 / 成长 / AOE）、评估权重偏移（在限定范围内）、风险姿态。代码把这些当作权重使用，不当作命令。 |

## 2. 经验怎么流动，怎么避免死套路
- 复盘子 agent 必须给每条教训打上类型：
  - **机制 / bug** → 代码事实 + replay 回归用例。45 局负局里 34 局属于这一类，修好后很少复发。
  - **安全** → 护栏。至少 2 局证据才能加。
  - **判断** → 只允许两种去处：(a) 评估项或权重，用 replay 离线调参；(b) 带触发键的提示（Boss / 敌人 / 遗物 / 界面 / HP 区间），记录出处、证据数和有效期。
- 禁止新写"情况 X 就选 Y"这种挑选规则。第 3 类里现有约 25 个规则族、约 150 个常数，逐步迁到 Δ 模拟和 intent 权重上。最该先删的是只凭 1–2 局得出的规则：Boss 卡牌加分、单局调整的卡牌分数、F1–3 事件 20% HP 线。
- 规则设预算，每半年净减少。提示连续 N 局没有可测效果就自动降级。这和 AgenticSTS 的结论一致：写入要设门槛，按场景触发的提示比整本手册有效。

## 3. Jev 能不能拿到我们的经验
能，但只能以数据的形式进去。`systemOne` 只有 `state` 和 `questions` 两个入口，没有 system prompt，也不能微调。三个做法：
1. 把判断预先算成每个选项上的标签，写进 `describePlan`：`setup_turn`、`hp_after`、`lethal_next_turn`、`wastes_block`。Jev 只按字面读，不会自己把规则套到盘面上。
2. 在 state 里加 `fight_hints`，放 ≤5 条、每条 ≤25 词、带条件的正面陈述，由代码按敌人和局面检索。
3. 从战斗 state 里删掉整份牌组和遗物清单。文档明确说，无关内容会降低 Jev 的准确率。

成本几乎为零：延迟在 1k 到 3k tokens 之间基本不变（约 530ms），多 300 tokens 每次约 $0.00001。绝不要塞整本手册：手册约 29 KB（8–9k tokens），而 Jev 现在的输入只有约 840 tokens。

## 4. 延迟和成本预算（每局 45–60 分钟）
- **现状**：每局约 379 个决策，其中 DeepSeek 约 33 次，按 12s 算约 6.5 分钟。其中约 15 次是战斗 plan+potion。
- **目标**：DeepSeek 每局 ≤25 次：约 8 个检查点 + 约 5 个事件 + 约 4 个商店 + 约 8 个接近的奖励，约 5 分钟。战斗里的 DeepSeek 调用全部移除。Jev 每局约 40 次，总计 <30 秒。
- **新增模拟算力**：每个奖励界面 ≤2 秒，即 4 个候选 × 2 场战斗 × 约 20 次 rollout；rollout 用剪枝的求解器当策略。每场战斗的药水判断 ≤1 秒。求解器目前的速度还没测，第 3 步第一件事就是测它。

## 5. 迁移步骤（每步都能单独验证）
0. **基线**：跑完正在进行的 10 局，固定以下指标：平均层数、每幕每场战斗的 HP 损失、相对最少掉血线多掉的 HP、每局 DeepSeek 耗时。10 局测不出胜率差异，所以用层数和 HP 作主要指标。
1. **Jev 提示 + 选项标签 + 精简 `run_brief`**：用 `replay.ts` 对已记录的 787 次接近决策做有提示 / 无提示的 A/B。达标：多掉的 HP 从 2.59 降到 ≤2.3，升级到 DeepSeek 的比例变化在 ±3 个百分点内。
2. **DeepSeek 退出战斗**，药水改用模拟：先 replay，再跑 5 局实战。达标：每场战斗 HP 损失不变差，每局 DeepSeek 耗时减少 ≥2.5 分钟。
3. **离线战斗模拟器**：从日志里的遭遇快照出发，以求解器为策略跑完整场战斗。达标：预测 HP 损失与实际的平均绝对误差 ≤8（FightPredictor 约 ±7）。
4. **ΔHP 卡值**：先只作为特征写进日志和 DeepSeek 的 state，再替换 Boss 卡牌加分和单局调整的卡牌分数。达标：幕 1 / 幕 2 Boss 战平均掉血下降，平均层数不降。
5. **DeepSeek 结构化 intent 映射到权重**：达标：第 3 类常数从约 150 降到 <60，同时 10 局的层数不降。
6. **地图 / 休息改用模拟成本**，复盘产出带类型的条目并进提示库。达标：同一死因在 10 局内的复发率下降。

## 6. 主要风险
- **模拟器保真度**：45 局负局里 34 局来自没建模的机制。模拟器一错，会同时拖累战斗和构筑，所以第 3 步的误差门槛不能放松。
- **未来抽到的牌未知**：Δ 模拟只看当前牌组，会低估成长型牌，需要加一个"成长"评估项来补。
- **样本太少**：A2 只有约 13 局，权重调参很容易过拟合 replay。调参时要留出一部分局不参与，每次只动少数几个参数。
- **DeepSeek 的 intent 可能不稳定或被忽视**：权重偏移要有上下限，也不能换模型后直接沿用。AgenticSTS 里为别的模型写的 skill 用在 DeepSeek 上反而 -18%，所以必须在 DeepSeek 自己身上做 A/B。
- **提示改变 Jev 的置信度分布**：升级比例会漂移，每一步之后都要重新校准各界面的升级阈值。
- **HP 护栏和成长牌的价值互相拉扯**（JEGBU7 就死在这个上）：要在评估函数里统一成同一种代价，不能靠两套规则分别调。
