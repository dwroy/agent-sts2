## 结论与边界

保留的 STS2 原生会话在主要窗口内输入 **1,511,815,340 token（15.12 亿）**、观测到 **8,988 次有效 usage 增量**，平均每次 **168,204 token**；上下文 p50 **159,250**、p90 **288,418**。缓存输入 **97.516%**，未缓存输入 **37,553,708**。运维输入占 **30.89%**，普通策略批次占 **22.11%**，应优先减少这两类的机械调用及反复携带的历史，而不是只调推理档位。

这不是账单或共享账号额度的测量：token 权重、缓存计价、服务端限额及其他项目用量不能从这些数字推出。缓存 token 仍是模型输入，但不能与未缓存 token 等价估算成本。此处“调用”是去重后的原生 usage 更新代理，不能保证覆盖没有 usage 的请求或失败。推理输出是输出的子集，不另加一次。

**当前交付是规划与只读审计，生产调度和会话档位尚未改变。** 没有停止当局/worker、没有新开模型/研究/对局/监听、没有改账号/home、没有读取凭据或 `.env`。只读辅助和学习者原沙箱保持。新源继续走原工作树、检查、live 锁和既有宿主验收，不能用本数据审计冒充上线绿。

## 大脑必须单列

大脑引擎在生命周期结束时清理自己的原生 rollout，导致本窗口 trace 中 533 条带 usage 结构的调用均缺对应原生文件；其中 360 条有正输入、173 条为零。这些记录来自项目 `logs/codex-calls.jsonl` 的固定字节截点，输入 **66,994,895**，缓存 **2,373,760（3.54%）**。模型/effort 字段均为 `gpt-6.1-sol/xhigh`。

它们没有计入上面的原生总数。去重后已知合计输入 **1,578,810,235**，缓存约 **93.53%**；未缓存 **102,174,843**，其中大脑占约 **63.25%**。因此不能把“全项目 98% 缓存”当 STS2 结论，更不能据此断言大脑成本很小。该合计仍是已知覆盖，不补造已删除或失败请求的用量。

优先沿已有 `codex-brain-cache` 任务核稳定前缀、请求构造和复用身份，避免同时新建研究。保持当前大脑模型、effort、调用节奏、预算、采样/四闸和 SL 已授权规则；如要把大脑也降档，须与开发/运维分开作为明确的行为实验决定，不能从炉石原有 medium 推到 STS2。没有生成新游戏知识。
