# #29：DeepSeek 超时追查与官方接口对比

任务来源：[Claude 转 Roy 的追加要求](https://github.com/dwroy/agent-sts2/issues/29#issuecomment-6313140049)。这是原速度实验的追加实验；原回执和原统计保留在[上一级目录](../README.md)，没有用重测数据补写旧失败的 token 或首 token 时间。

## 结果与判断

**原 30 秒 deadline 经常不足以完成长推理；本批没有观察到网关长时间排队或持续吞吐偏低。** 两端各 25/25 严格首答及引擎校验通过，均 HTTP 200、完整流、正常 stop，无格式修复、重问、限流、5xx 或 300 秒超时。原 15 次超时记录在两端均完成；其中 Nova 11/15、官方 9/15 这次仍需超过 30 秒。10 道旧成功对照中两端也各有 1 道超过 30 秒，快慢不是稳定的二元题目标签。

|端点/旧基线|n|均值秒|p50/p90 秒|首 token p50/p90 秒|流式 token/s p50|推理 token p50|
|---|---:|---:|---|---|---:|---:|
|Nova Flash|25|39.93|29.09 / 82.35|0.92 / 1.50|191.45|5,591|
|官方 Flash|25|37.41|25.36 / 71.72|1.00 / 1.69|186.96|4,564|
|旧 GPT xhigh，同题权重|25|46.07|44.49 / 73.98|未采样|未采样|见原回执|
|旧 GPT high，同题权重|25|16.95|15.80 / 22.74|未采样|未采样|见原回执|

**慢在生成较长推理的证据较强。** 两端首个答案内容的 p50 分别为 28.17/25.09 秒，而首个推理 token 约 1 秒；输出 token 的约 98.8%/98.9% 是推理。总耗时与推理 token 的 Pearson 相关系数为 0.997/0.992。整批最长内容分块间隔分别为 2.93/1.14 秒，没有观察到几十秒无内容的长停顿；两端交付吞吐中位数相近。TTFT 包含网络、排队、预填充等，不能从这些数据单独识别真实队列长度，更不能把相关性当作底模相同的证明。

同题长度差异有双向例子，不能将单个慢答认作固定网关开销：

|样本/题型|Nova 秒 / 推理 token|官方 秒 / 推理 token|
|---|---|---|
|s09 q23 路线规划|144.98 / 29,298|45.16 / 9,625|
|s15 q28 幕初计划|29.09 / 5,591|142.52 / 27,924|

q23 在过程口头更新中曾被误称为幕初计划，这里按冻结的 `map/route-plan` 更正；分组脚本始终依据原 label，统计没有受影响。q23 官方第二次为 120.51 秒、27,479 推理 token；q12 Nova 两次为 20.79/43.77 秒、3,320/7,982 推理 token，同端点同题也有明显波动。

**关于旧超时的结论边界：** 原回执和客户端定时器证明请求被 30 秒限制截断；本次证明这些题在放宽预算后可以有效完成，且经常需要长于 30 秒的持续推理。旧失败没有首 token/流式轨迹，本次又改了流式传输并跨时重测，无法排除旧请求当时的拥堵或后端变化，也不能确定每个旧失败原本还需要多少时间。两端 checkpoint 未证实相同，回答不同还可能包含采样与服务端实现差异。没有进行对局质量、胜率或长期可用性验证。

**每局估计必须看权重。** 直接 28×本批均值，Nova/官方/旧 xhigh/旧 high 为 18.63/17.46/21.50/7.91 分钟；这批刻意多选慢题。按历史 20 局题型频次加权后为 8.87/9.63/16.99/6.76 分钟。两者差别来自拿牌等自然高频题在本批占比较低；题型内部慢题偏重仍未消除。按 18 道独立题的题内均值再平均，Nova/官方为 32.82/30.76 秒。完整分题型和逐局区间见 [tables.md](tables.md)。原报告的 32 题总体基线仍独立保留，不与本子样本混算。

**本次 54 次物理 API 请求**：50 次生成、2 次模型查询、2 次余额查询；新增 Codex 调用 0，原任务累计仍为 96 次原生测试调用。官方账户在 09:58:20–10:31:34 UTC 测试窗口净扣 **¥1.33**，不公开余额；未排除账号并发用量。Nova 实扣未知。按统一官方峰时价格、各端实际 usage/cache 计算的参考额分别为 $0.232409/$0.413874，不是实际账单；官方多数请求在低峰，且两端缓存命中量不同，不能据参考额认定实际成本高低。

本次支持先将 DeepSeek 的规划长尾、等待预算和实际对局质量纳入后续验证；没有足够证据据此选择新的生产大脑。现行引擎、effort、账号、共用配置和 live 均保持原状。

## 设计与边界

- 原实验的全部 15 次 DeepSeek 超时记录对应 **8 道不同题**；保留每次记录，另选 10 道互不重复、且与这 8 道不同的成功题作为对照，共 25 个配对样本、18 道独立题。两组交错，奇数样本 Nova 先、偶数样本官方先；所有调用顺序执行。没有只挑重测成功的题。
- 每题每端只发一次物理生成请求，超时改为 **300 秒**，启用 SSE 和 `stream_options.include_usage`。冻结生产引擎生成的原始 messages、thinking、reasoning_effort 和 JSON 模式；仅替换端点/模型 ID、增加流式字段。拿牌等原本使用 `high` 的题保持 `high`，策略规划等原本 `max` 的题保持 `max`。未设置新的 `max_tokens` 上限。
- 用原引擎做同样的解析、规范化和 spec 校验；同时单列首答严格 JSON 校验、流是否完整、finish_reason、恢复和被阻止的修复请求。传输适配器禁止第二次 HTTP 请求，不做自动重试或提供方回退。通过表示满足离线契约，**不代表策略正确或通关收益**。
- 首 token 指第一个非空 `reasoning_content` 或 `content`，排除 role 和心跳。记录响应头、首推理、首答案、最后内容、每个 SSE chunk 到达时刻，以及完整推理/答案。流式 token/s 用 usage 输出总数除以首个至最后一个有效内容 chunk 的时间，受分块与缓冲影响，是交付速度近似，非原生解码速度。wall token/s 另用总耗时作分母。输出 token 已包含推理，不能相加两次；答案 token 按输出减推理计算。
- 失败也计入延迟分布，p50/p90 用线性插值。按题型和旧成功/超时组分别统计，另保存 18 道独立题的题内均值；小样本分位数和重复记录不具有独立大样本的统计效力。
- 请求在专用进程中以 `nice 19` 执行；进程树抽样见 `process-receipt.json`。未调用 play，未修改生产账号、共用配置、引擎选择或 live/STOP。官方凭据仅在本机只读、仅用于这次授权测试；没有打印或复制凭据。生成内容只作实验输出，没有写入游戏知识库。

## 模型是否相同

先顺序查询两端 `GET /models`，原始白名单字段见 `models.jsonl`。官方返回 `deepseek-flash`，名称 `DeepSeek-V4.1-Flash`，声明支持 `low/high/max`；[官方模型文档](https://api-docs.deepseek.com/quick_start/pricing/)在核验时将该 ID 对应到 `DeepSeek-V4.1-Flash-1017`。Nova 仅暴露 `deepseek/deepseek-flash` 别名，没有底层 checkpoint/版本。**本实验不能证明两端是同一 checkpoint**，因此结果是对应 Flash 别名、相同请求档位的端点对比，不能把回答长度差异确定归因于网关或确定归因于模型版本。

请求中保留了相同的 `reasoning_effort`；服务端没有回显实际执行档位，不能单凭请求宣称核实了内部计算预算。官方能力声明和请求语义参见[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。流式格式与默认输出预算参见[Chat Completion 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。来源核验时间与事实摘录见 `sources.json`。

## 费用口径

官方测试前后各查询一次账户余额，仅公开测试窗口的净变动、时间和私有回执 SHA，不公开余额。净变动仍可能包含同一账号的其他使用，不能完全归属本测试。Nova 无可归属的实扣账单，实际费用保留未知。

为方便对照，另按同一公开峰时标价计算两端 token 的参考金额：每百万未命中输入 $0.30、命中输入 $0.006、输出 $1.20；低峰为一半。费率来源是[官方价格页](https://api-docs.deepseek.com/quick_start/pricing/)，不是 Nova 合同价格。测试跨过 UTC 10:00 的高低峰边界，统一峰时参考额不等于实际扣费；也没有做币种换算。缓存兼容顶层 `prompt_cache_hit_tokens` 与嵌套 `prompt_tokens_details.cached_tokens`，缺 usage 不作零费用。

## 证据与离线重算

- `sample.json`：冻结选择、顺序与旧记录关联；`requests.json`：冻结的生产首请求及 SHA。
- `results.jsonl`：每次结果、时延、原始 usage、校验与错误分类；`streams.jsonl`：完整答案/推理和逐 chunk 时间，包含失败时已收到的片段。
- `accounting.json`：公开字段的物理调用预登记和测试窗口净扣费；`call-counts.json`、`costs.json` 为派生结果。私有余额原件留在本地忽略目录，不进提交。
- `summary.json`、`per-request.csv`、[分题型表](tables.md)：派生统计、费用、每局估计、同题旧 GPT 对比与 SHA 清单。GPT xhigh/high 全部沿用原回执，没有新增 Codex 调用。

```bash
nice -n 19 /usr/bin/python3 -B agent/tools/issue29-deepseek-report.py
```

重算不联网、不读 Key；冻结的公开 `accounting.json` 足够，不依赖私有余额文件。脚本核对请求 SHA、流文本/分块长度和物理调用对应关系。验证范围、退出状态与日志 SHA 见 `verification.json`。

历史 20 局平均 27.8 问。每局估算同时给出 28×本批均值及历史题型加权值；同题旧 GPT 用相同 25 个记录权重，C 只有第 1 轮，重复题会复用该回执。题型内仍刻意偏重旧超时题，且 GPT 与本次采样时间不同。原 32 题总体估计与这个子样本不能混为同一抽样分布。请求时间估算不含 Jev 出牌、游戏动画、局间学习，也不是整局时长或保证正确答案的耗时。
