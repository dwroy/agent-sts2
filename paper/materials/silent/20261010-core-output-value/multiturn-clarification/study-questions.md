## 本次必须直接回答的多回合问题

本节是 Roy 对原七项交付的细化，采用相同 204 局冻结输入、同一 request、同一标准验收和经验沉淀通道。具体牌、遗物、机制和建议只能由学习者回查静默原始对局得出；不把运维的抽象概率示例作为事实或指定结论。

1. 在核心组合已具备的样本中，识别需要重复的部分，以及实际先后到手、可打和生效的过程。分别核单张与多张组件、多个回合的实际兑现次数、持续效果与实际伤害；回答提高整套使用次数的主要限制是什么。
2. 从证据识别增加现有牌数量、战内生成副本、重放以及再次取用等实际存在的过程。核目标、触发条件、效果发生时点、费用、手牌与牌堆去向及其他限制，不能把未观察的通用机制写成确定规则。
3. 列出有实盘依据的具体卡牌、遗物及来源局号。说明观察到多少件/张、实际增加多少次核心效果，哪些数量与组合从未观察，哪些只有组件效果而没有整套收益证据。给条件化数量建议时必须有依据，不预设一张/两张最优或所有核心都需要复制。
4. 比较跨多回合的新增收益与启动成本、等待、资源占用、抽牌机会以及实际生存代价，识别可能帮助和可能妨碍核心兑现的情形。研究多组件的配比与同时/先后可用条件；不能仅以副本数量或同 ID 出牌次数代替完整组合兑现。
5. 对“在大多数抽牌情况下”给明确分母和可复算口径。先报告真实抽牌序列与兑现分布；若建立概率模型或离线反事实，逐项说明从证据核实的机制、随机性/保留/洗牌/费用等假设、命令、种子与误差或精确算法，和真实观察分别报告。不能只挑理想手牌，也不能把合成结果冒称独立实战、胜率或因果改善。
6. 在已成型条件下比较牌组规模和新增牌的功能，回答增加、跳过、移除或替代何时可能提高/降低核心使用频率；考虑配件、资源和生存收益，不能仅凭牌数相关性断言越多越好、越少越好或固定最优张数。
7. 面向 Roy 的首段必须给出明确可用的结论及最重要的条件；有数据就给具体牌/遗物、数量范围及适用组合，没有足够数据则列清缺口和候选。将足够证据的新增指导与原四核心、牌组规模、能量/循环经验去重，经既有 ledger/code_proposals CLI 和 experience-update 沉淀，保持原状态、失败和未知。

以上分别并入原 `startup_and_scaling`、`sustained_output`、`resource_survival_tradeoffs`、`construction_execution_guidance`、`counterexamples` 和 `limitations` 的正文；`damage_realization` 仍核实际输出。标准 JSON 的七个 coverage 键不变，必须在 objective_conclusions 中直接覆盖本补充问题。
