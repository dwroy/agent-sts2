## 紧凑投影与知识边界

`boss_dossier` 连同字段名、JSON 转义和必要来源标签以 UTF-8 **1500 字节**为硬上限，不按字符计。不把完整来源账本塞进模型题面；模型内保来源种类、当前绑定身份/短引用、分母、观察限定及按 Boss ID 查询细节的现有工具入口，审计侧保完整版本、叶子 SHA、条目 ID/原证据窗口。

开局保六个 Boss 的短行和三幕有序路径。揭晓后，用腾出的目录空间补当前目标的适用风险、策略及资源预算，仍保留最终连战目标。超限按固定展示层级移除完整可选字段并明确 omitted/unknown，保留目标身份、来源限定、分母和反证指针；不截断句子/数值，不按牌值或胜率选 Boss/选牌。这是展示预算，不是决策排序。

威胁/需求只机械投影适用的已发布内容或已核日志事实。不能从 Boss 名称、单场动作窗口、外部终局牌组自行总结“必须群伤/虚弱/驱散”等新规则；没有现成依据就 unknown，并让脑明确自己的暂定缺口假设。新知识仍交原学习链，不由本开发补齐。

## `boss_target` 与计划合同

建议新增结构化对象，便于校验与统计，例：

```json
{"boss_target":{"boss_ids":["TEST_SUBJECT"],"gap":"启动后持续防护是否足够仍unknown","reason":"本步对该缺口的作用由大脑结合实际选项说明"}}
```

`boss_ids` 为去重的当前题面规范 ID 数组，最多 3 个；`gap`、`reason` 为非空字符串，分别最多 80/120 Unicode 字符。可以指已知 Boss 或有来源的候选；不得以此字段宣称候选已揭晓。不补 Boss 缺口时 `boss_ids=[]`，`gap` 明确“本步不补”，`reason` 说明保血/过当前幕等实际目的。缺口未知合法，纯空白、无理由或瞎编 ID 不合法；代码只检查格式和引用，不裁决打法。

范围沿现有 Silent A10 非战斗 `isConstructionQuestion`，覆盖选牌/跳牌、商店计划及实际购买题、休息、删牌/升级选择、事件和相关 bundle/capstone，以及挂载/独立 run-plan/路线规划。战斗内 selection 不加。首次计划把候选有序组合及各目标缺口写入原 `endgame.win_condition/gaps/resources`；揭晓变化的首道构筑题必须明确复核这三项，未知后场不得抹掉。沿原 patch 合同只提交受影响字段并说明沿用或修改，不要求每题重写整局计划或重算路线。

题型 schema、stableSchema、Codex strictSchema、DeepSeek 接受路径、运行校验与日志必须一致。格式失败沿原重问/失败处理，不由代码代填 boss_target 或重写大脑选择；每题原回复、校验失败及最终接受结果都留存。计划保存/重启/跨 SL 不能读入未来揭晓的身份或未来楼层计划。
