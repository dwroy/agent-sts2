# F48 慢算诊断与联合日志暂停

2026-10-17，原 watcher，父项 `roy-20261016-global-build`。仅离线读取现有日志；没有开局、模型调用或新增模拟。

## 结论

**原始计时不支持 `7ca593f9e / f48-joint-shadow-v1` 导致 20 倍慢算。主要耗时是原有 B2 连续 Boss worker 的实际计算。** 联合 shadow 是在 `runLines` 完成之后汇总现有结果；`boss_sim.ms = run.elapsedMs` 在汇总之前已经计完。CVJ4 的这一段累计 **310.84 分钟**；汇总所在的 `other_ms`，连同排名、文本等其他规划开销，全部合计仅 **34.456 秒**。没有独立的联合汇总计时字段，因此不能把 34.456 秒全部算作它，实际联合汇总耗时仍未知，但该上界排除了数小时归因。

两局原 `boss_sim.objective` **都已经是 `F48_F49_continuous`**。`7ca593f9e` 添加的是现有样本的日志汇总，不是首次开启两战模拟；不能把“暂停这份联合日志”和“停止原有 B2 两战计算”混为一项。

用户要求先停联合 shadow，另准备了纯诊断默认关闭开关；**关闭日志不能消除本报告定位的 B2 成本**。未缩减 B2 候选、样本、worker，未改 C1/C2、题面、排序、SL 或用药规则。

原 B3 `ms` 包含跳过/失败记录；组合字段仅在有完整 global 计时的记录出现，不能把三列当严格会计恒等式，也不能重复加总。F48 主耗时不在这些字段。

历史逐题 `load1` 中位数 14.89 → 33.43，p90 33.12 → 45.56，CVJ4 最高 57.26；固定主线程速度探针中位数 2.85 → 2.92 ms，p90 3.16 → 3.21 ms。负载较高是真实伴随现象；探针没有 20 倍退化，不能凭 loadavg 把整个差额归给机器。

CVJ4 F48 的原控制台有连续的 `required simulation boss-lines: ... sample outcomes` 心跳，样本数随分钟增长。例如 01:17–01:22 的第一题从 2104/18000 逐步到 14200/18000；耗时已经发生在 worker 返回前。两份覆盖 F48 的控制台没有 ENOSPC/EIO/EROFS/心跳写失败记录。79 条联合 JSON 约 2.48 MB，无法仅凭体积支持数小时 IO 归因。

**没有同期磁盘 IO 等待、延迟或吞吐采样，IO 因果保持 unknown。** 原 ops 03:34 剩余 7.76 GiB、04:42 约 1.22 GiB、04:49 约 0.67 GiB 的磁盘压力及归档活动另列为风险背景，不等同 IO 等待测量。23:33 的 ENOSPC 在 F5，不作为 F48 原因。
